# AI Video Studio 官网与桌面版下载设计（已确认）

日期：2026-10-30。产品负责人：当前会话。目标读者：前端、发布负责人、测试。用户已选择官网 `/`、创作 `/studio/`、先用现有 HTTPS IP，并要求最新版 Web 与 PostgreSQL API 同次上线。

## 1. 意图与当前证据

新访客需要先弄明白产品能做什么，再选择使用网页端或下载 macOS 桌面端。官网要解释从一句想法到逐镜头编排的路径，突出新手容易开始、用户能控制每次生成，并提供真实可用的下载文件。

当前 `https://39.108.55.176/` 是网页创作应用。服务器的 `sr-nginx` 将 `/` 指向其静态目录，将 `/api/` 代理到独立 API。桌面仓库只找到 `AI Video Studio_0.1.0_aarch64.dmg`，约 3.2 MiB、arm64；`hdiutil verify` 通过，但包内 App 的 `codesign --verify --deep --strict` 失败（`code has no resources but signature indicates they must be present`），`spctl` 拒绝，且没有公证票据。此文件不可直接作为官网公开下载的验收包。现有线上 API 仍在旧 SQLite release，当前仓库的 PostgreSQL 改动尚不能据本地测试认定已上线。

功能证据来自 [README](../../../README.md)、[首页与画布 PRD](../../product/2026-10-29-unified-home-creation-prd.md) 和[独立验收](../../acceptance/2026-10-29-unified-home-creation.md)：一句话/关键词得到三个不同的单镜头方向，用户选择和编辑；手写提示词或完整剧本进入项目；参考照片、项目与分集、逐镜头确认；画布节点与时间线；桌面本地项目。网页版整集导出、真实供应商生成和桌面原生崩溃恢复尚未完成相应验收，不作为官网承诺。

## 2. 目标、非目标与失败边界

- **目标**：首次访问 10 秒内看懂“输入想法 → 选/改方向 → 建项目 → 镜头或画布”；在首屏能找到网页版和桌面版两种入口；下载得到完整且可安装的 Apple Silicon DMG；刷新或直接访问 `/studio` 不丢工作台。
- **非目标**：重做创作应用界面、增加账号或支付系统、介绍模型参数与供应商、承诺免费生成、上线 Intel/Windows 安装包、宣传自动拆镜和网页版整集导出。
- **不能接受**：官网按钮下载损坏或旧版本 DMG；把未验收功能写成已上线；下载失败时静默跳回首页；为营销站迁移或覆盖用户项目数据；使用参考站的品牌素材或文案。

用户已选择按 A 实施；上线 URL 先用已验证的 HTTPS IP，日后绑定域名时保持路径不变。现有 `/api/` cookie 与请求路径保持不变，官网不接触会话。

**已选择同次发布最新版**：线上当前是旧 SQLite API release，本地最新首页、原文和画布流程依赖 PostgreSQL 版接口。因此数据库迁移、API 切换、用户数据备份与恢复测试都是本次发布的前置条件。新官网必须在最新版工作台公网实测通过后才公开承诺对应能力。

2026-10-29 的[线上部署回归记录](../../../.codex/.agent/deployment.md)还指出三版文字灵感的真实供应商调用当时返回 `provider_error`；仅有服务端凭据和 HTTP 认证成功，不代表该体验可用。官网首屏如果主打“三个镜头方向”，上线前必须修复并以隔离账号完成真实三版生成验收；若供应商仍不可用，官网主标题和能力区要改成已验证的手写创作路径，不能把失败功能当卖点。

2026-10-30 公网最新版真实测试仍是 `failed/provider_error`，获得 0 版，视频额度未变化；官网已按上述门禁切换为“自写想法或剧本 → 项目 → 单镜头/画布”主叙事，三版方向仅标“即将开放”。

## 5. 关键交互

1. 官网不要求登录。顶部“产品能力/创作流程/桌面版/常见问题”滚动到对应锚点；“进入网页版”和首屏“开始网页版创作”打开同源 `/studio/`，保留正常浏览器前进/后退。
2. 首屏“下载 macOS 测试版”先滚动到 `#download`，让访客看清平台和安装说明；下载区的“下载 DMG”才直达版本化文件，且只在服务端文件存在并通过发布门禁后启用。下载区显示 Apple Silicon、版本、文件大小与 SHA-256；点击“复制校验值”后给出可感知的成功/失败状态。
3. macOS 安装说明以显式展开组件呈现：拖入 Applications、首次运行若被 Gatekeeper 拦截，按 [Apple 官方的“仍要打开”操作](https://support.apple.com/en-au/102445)处理；不得要求用户关闭 Gatekeeper 或运行 `xattr -d`。未持有 Developer ID 时清楚标记“未经 Apple 公证的测试版”。
4. 站点截图有“网页端实际界面”或“桌面端实际界面”的标注，不用生成画面假冒产品截图。所有功能措辞注明作用域，例如“桌面端本地导出”不可写成“全平台导出”。
5. `/downloads/` 请求不存在的版本时返回 404；临时服务器故障给出非 HTML 的下载失败响应。官网在可访问性、窄屏、键盘和无脚本基础阅读上仍可使用。

## 6. 发布设计与验收门槛

- 采用独立静态官网构建和现有网页应用构建。Nginx 保留 `/api/`，新增 `/studio/` 的 SPA fallback、`/downloads/` 的静态文件响应，最后让 `/` 指向官网。旧静态目录和 Nginx 配置先备份；改动先 `nginx -t`，切换后核对根页、`/studio/`、`/api/health` 与下载文件，失败回滚两份静态目录及配置。
- DMG 发布前：按照 [Tauri 官方 DMG 构建](https://v2.tauri.app/distribute/dmg/)与[ad-hoc 签名说明](https://v2.tauri.app/distribute/sign/macos/)对**新构建**执行容器校验、包内 App 的 `codesign --verify --deep --strict`、版本/架构核对、只读挂载、复制到 Applications 并实际启动，记录 SHA-256；下载上传后再对公网文件取回哈希并核对 `Content-Length`、`Content-Type`、HTTP Range。无 Developer ID 的包无法通过 Apple 公证，用户会遇到 Gatekeeper 确认步骤；这属于测试版说明，不是可跳过的验证。
- 服务器当前已核实可通过既有临时部署密钥进行只读 SSH；正式上线前仍需确认该入口可写且目标目录与备份空间足够。官网文件与 DMG 不触碰 `/var/lib/ai-video-studio` 的用户数据，也不将本地尚未部署的 PostgreSQL API 改动混入静态站点发布。
- 独立测试最终交付：正常和窄屏官网、功能区、下载区、真实浏览器点击、实际下载、安装启动、`/studio/` 与 API 健康、404/失败状态的结果及截图；代码与部署证据按同一版本号归档。无法实测项明确记为未验收。

## 7. 留给实现者的决定

前端可选择原生 HTML/CSS 或复用 Vite 构建，但官网须独立于创作应用，可静态生成、无需 API 才能展示。具体分镜图形由前端使用自有截图与 CSS/SVG 制作；图片不得暴露测试账号信息。下载清单可以是静态 JSON，由发布流程在通过 DMG 门禁后写入；不能把本地 `target/` 路径直接变成对外链接。
