# 可灵图生视频与断网恢复

用户选择一个已有分镜和照片，明确点击“生成”后，桌面端才向可灵提交一次付费图生视频任务。首版仅接无声图生视频；有台词的分镜继续保留草稿，等配音和动物口型流程单独接入。

## 方案

考虑过由 MCP 工具直接调用可灵、由 Agent Harness 调用可灵，以及桌面原生服务适配器。选择原生适配器：固定工作流需要可控的持久化与成本边界，MCP 和 Harness 可以以后调用同一组经过校验的业务命令，无需成为本轮生成链路的依赖。

## 提交与恢复

- Rust 从本地私有配置读取 `KLING_API_KEY`，直接调用可灵图生视频 API。前端只拿任务状态，不能得到密钥。
- 每次用户点击生成都产生新的 UUID 作为 `external_task_id`。发送网络请求前，先把 `submitting` 任务写入 `project.json`；收到可灵 `task_id` 后立即持久化。一个未完成的分镜不接受再次提交。
- POST 超时、断网或应用崩溃时，任务保留为 `unknown`/`submitting`。恢复操作只执行 GET 查询：优先远端 `task_id`，没有时使用 `external_task_id`。查询不到不能证明创建失败，因此禁止自动重新 POST。
- 查询成功后把状态持久化。视频生成完成时先下载到 `media/generated` 临时文件，成功落盘后再记录生成素材；下载失败时再次查询只重试下载，不重新生成。
- 首版只允许可灵 `kling-2.5-turbo` 新版图生视频 API，生成 720p 无声 5 秒或 10 秒镜头。页面生成前明确告知会产生可灵费用；准确价格以用户的可灵控制台为准，不伪报旧的 Hedra 价格。

## 验收

本地模拟可灵服务验证：一次提交产生一个任务；提交响应丢失后只能查询；重开项目仍能找回任务；状态查询失败不触发 POST。完成任务的视频下载逻辑通过代码审查，尚无真实付费服务验证。真实付费调用只在用户自己点击“生成”且配置有效 API Key 后发生。
