# AI Video Studio：Agent 优先的多端架构复盘

状态：面试演示项目的设计稿，等待用户审阅；本稿不授权修改产品代码。取代 `2026-10-27-multiplatform-plugin-architecture-design.md` 中“网页和移动端暂不共享本地项目”的阶段假设。保留旧桌面项目的打开、离线手动编辑与导出能力；付费生成统一迁往登录后的云端执行。

## 已确认的目标

- 桌面端和网页端打开**同一个项目与分集，并在首次关联后自动同步**。用户在任一端看到的素材、已生成视频、任务和编排结果应一致。
- 网页端首版**开放其他用户注册**，每个账户的项目、素材、任务与演示额度记录相互隔离；首版不做多人同时编辑同一项目或团队共享。
- 这是**面试演示项目**：用户注册登录后使用平台后台管理的 Agent 模型及可灵密钥；用户不填写 API Key，不接入真实充值或支付系统。后台为每个账号设置演示额度与调用限制。
- 产品主路径是**用户输入 → Agent 执行 → 实时反馈执行状态与结果**。关闭页面或断线后仍能找到原运行记录。
- 首个完整闭环是**上传照片 → 输入需求并选定分集 → 确认付费生成 → 得到视频 → 自动加入该分集**。加入分集不等于自动排入整集时间线。
- 每次有外部副作用的操作都有持久 ID；响应不明时查询原任务，不能因重连、刷新或 worker 重启重复提交付费生成或发布。
- 桌面端包括旧本地项目在内，**所有新生成都要登录并走云端**。未登录或项目尚未关联云端时仍可离线手动编辑，但不能提交生成。
- 画布是独立注入的功能插件，桌面与网页可用；移动端不注册、不渲染画布。移动端仍可输入需求、查看分集、任务和结果。
- 已选的 C4 奶油胶片及青蓝夜幕换肤覆盖桌面与网页的共享内容组件；桌面原生窗口栏是平台壳，不复制到浏览器。

## 现状与缺口

仓库已有 pnpm workspace、`project-core`、`platform-ports`、静态插件注册，以及 `ui-web` 的 Button、Panel、StatusBadge。`design-tokens` 仍是单套旧颜色；生成页、画布页和大量 C4 色值直接位于桌面 `Studio.css`。Pen 里的双主题变量只是设计交付，尚未成为应用样式。

当前插件契约只有平台、依赖和面板列表，没有路由、节点类型、存储迁移或 Agent 工具贡献。画布由 `StudioWorkspace` 直接渲染，分集、人物、片段和节点图同放在 `ProjectManifestV2.studio`。目前没有网页、移动或服务端应用。

桌面可灵流程会先将本地任务写为 `submitting`，再以该任务 ID 作为 `external_task_id` 调用供应商；未知结果可查询，避免自动重复 POST。这是单机生成任务恢复，不等于跨端 Agent 运行、实时事件流或云项目同步。迁移时把该恢复原则搬到服务端；桌面端不再直接发起新的可灵 POST。

## 方案比较与建议

| 方案 | 结果 | 判断 |
| --- | --- | --- |
| 各端各自保存项目并运行 Agent | 起步快，但任务、费用、密钥和项目版本会分叉 | 不满足同一项目自动同步 |
| **云端统一项目与 Agent 运行账本，桌面保留本地缓存和离线编辑** | 一套任务状态与权限；需要项目迁移、素材上传和冲突界面 | **本稿建议** |
| 一开始拆成微服务并支持任意动态第三方插件 | 扩展面广，部署与权限成本高 | 当前没有必要 |

采用第二种：服务端是**云项目、AgentRun、付费操作与事件日志的权威来源**，也是所有平台唯一的新生成提交者。桌面保留本地项目目录、素材缓存、离线手动剪辑与本地导出；登录并关联云项目后可提交生成。网页和移动端只通过带身份鉴权的 API 访问项目。插件仍是仓库内编译期注册；暂不执行任意第三方运行时代码。

## 核心执行路径

```text
桌面／网页／移动输入 ──带 clientRequestId──> API 创建或返回同一 AgentRun
                                         │
                                         ▼
                              Agent 执行器读取项目快照
                              → 规划步骤 → 权限／费用检查
                              → 等待必要的用户确认
                              → 逐步调用插件提供的受控工具
                                         │
                         持久 RunEvent 与操作记录
                                         │
                        SSE 推送／断线按序号补读／状态查询
                                         │
                              三端展示真实执行状态

画布插件 ──提交同一套领域命令或 Agent 输入──> 上述执行路径
```

画布不是第二套执行引擎。它负责可视化编排、节点验证与用户逐节点触发；直接输入的用户即使不用画布也能完成生成。保留第一版“逐节点运行”的决定：Agent 可规划多步，纯元数据步骤按确认后的计划执行；付费生成和发布必须单独显示范围与费用并等待明确确认。连线、重连或打开项目不会自动扣费。

首个 Agent 闭环只实现一个受控生成步骤及成功后的分集归档：用户先登录、上传照片、选定已有分集或明确新建分集，再输入自然语言镜头需求；Agent 将其整理成可检查、可修改的镜头计划（照片 ID、动作场景提示、允许的时长、目标分集），检查所有引用和演示额度，展示调用确认；确认后生成并持续反馈状态。Agent 只能使用用户选定的照片和分集，不能自行指定其他项目素材。成功视频作为该集的镜头结果保存，画布插件在桌面和网页中显示对应视频节点；移动端以普通镜头卡显示同一结果。时间线排序、剪辑和整集导出继续由用户操作，不由首个 Agent 运行自动完成。失败或未知结果不会伪装成可用镜头。

### 标识与持久状态

| 记录 | 作用 |
| --- | --- |
| `clientRequestId` | 客户端为一次用户意图生成的稳定请求 ID；相同 ID 与相同输入重试只返回原 `runId`，不同输入复用该 ID 应拒绝。 |
| `runId` | 一次 Agent 运行，关联项目、输入摘要、项目版本、执行计划、状态和事件。 |
| `stepId` | 运行中的一步，便于续跑时识别已完成步骤。 |
| `operationId` | 每次付费生成、导出或发布等外部副作用的内部操作 ID；在调用外部服务前落库并与批准记录绑定。 |
| `externalTaskId` / `remoteTaskId` | 发送给供应商的关联 ID 与供应商返回 ID，二者都保存；不与 `runId` 混用。 |

服务端对 `(用户或项目, clientRequestId)` 和 `operationId` 建立唯一约束。worker 可重试**读取、查询和幂等的内部步骤**，但对外部 POST 只在确认尚未发出时执行。若响应丢失，先凭已保存的外部 ID 查询供应商；若供应商不支持查询或幂等，保持 `unknown` 并进入人工核对，不能宣称“恰好一次”或盲目再 POST。用户明确重新生成时创建新的操作 ID 与新的确认记录。

`RunEvent` 至少包含 `runId`、递增序号、时间、步骤、状态、用户可见说明和可选结果引用。状态可覆盖：已接收、规划中、等待确认、待提交、供应商排队、执行中、下载中、已保存、失败、结果待确认。前端不合成供应商未提供的完成百分比。网页和桌面前台订阅 SSE；重连按事件序号补读并以运行快照校正。移动端前台可订阅或查询，后台通知只作提醒，打开时仍读权威状态。SSE 是单向状态通道，提交命令继续走带幂等 ID 的普通请求。

## 同一项目自动同步

### 数据归属

- `project-core` 管理项目、分集、人物、素材引用、镜头、时间线结果、发布文案和版本规则；Agent 任务及外部操作在服务端独立保存，项目只引用其 ID／最新投影。
- 画布插件管理带版本的 `GraphDocument`：节点、边、坐标、视口与节点配置。它通过稳定 ID 引用核心人物、素材、镜头和分集。关闭插件或从移动端打开项目不会删除图数据。
- 云端保存项目元数据与不可变媒体对象。桌面保存可离线使用的本地副本和素材缓存；浏览器拿对象引用或受控下载地址，不接触桌面绝对路径。媒体与任务日志不塞进一份频繁整体覆盖的 `project.json`。

### 首次关联与日常同步

已有纯本地项目首次登录云端时做一次可见的关联迁移：检查文件、上传素材、建立云项目及本地 ID 映射；上传和校验成功后才标记为自动同步，失败不覆盖原项目。关联记录绑定当前账户；切换账户时不得把同一目录悄悄上传到另一账户。新建云项目在桌面、网页使用同一个项目 ID。之后桌面编辑先写本地操作队列；联网时以稳定命令 ID、目标资源和 `baseRevision` 上传，服务端确认后更新本地同步位置。网页编辑直接提交相同领域命令。新生成的视频先落云端对象存储，再更新项目引用；桌面按需下载本地缓存。

断网时允许手动修改文本、编排等本地操作并标记“待同步”；Agent 运行、付费生成与发布需要登录且在线，不在断网时暗中排队等待自动扣费。未关联云项目的旧本地项目也不能再发起新的本地生成；应提示先登录并完成关联。同步冲突按**具体分集或素材元数据**暂停并显示本地／云端两版，由用户选择或手动调整；不静默覆盖或自动合并。无冲突的其他资源可继续同步。不可变媒体按内容标识去重，删除以版本化操作传播，避免一端离线时误删另一端新素材。

现有 `ProjectManifestV2` 的稳定项目、人物、镜头、任务和素材 ID 在迁移中保留。旧 `studio` 里的分集内容与图数据拆开，提供版本迁移、备份与失败回退。已有 `unknown` 可灵任务只能按原 ID 核对，迁移不触发新生成；若旧任务需要原本地凭证才能查询，可保留一次性只读查询入口或提示用户到供应商控制台核对，绝不因此发起新的本地 POST。

## 插件、UI 与平台边界

`plugin-sdk` 从“提供面板”扩为声明：插件 ID／版本、支持平台、路由或面板、能力、节点类型、领域命令、Agent 工具、权限、数据版本和迁移函数。宿主只装载该平台允许的插件，并在运行前检查依赖与权限。首版仍为静态注册。

| 能力 | 桌面 | 网页 | 移动 |
| --- | --- | --- | --- |
| 输入需求、查看 Agent 状态和结果 | 有 | 有 | 有 |
| 项目、分集和素材 | 本地缓存＋云同步 | 云端 | 云端轻量视图 |
| 画布插件与节点编辑 | 注入 | 注入 | **不注入** |
| 生成插件 | 经受控任务 API | 经受控任务 API | 提交意图／确认／查看状态 |
| 详细本地剪辑和 FFmpeg 导出 | 有 | 后续由云端能力提供 | 不提供 |

桌面与网页共用 `ui-web` 的无平台依赖组件：输入区、素材选择、运行状态、结果卡、分集列表、对话框、按钮与节点基础外观。画布的节点与连线组件留在 `plugins/canvas`。`design-tokens` 提供 C4 和青蓝两套语义变量；`ui-web` 组件消费变量，桌面和网页共用换肤状态。桌面 48px 原生窗口栏由桌面壳承载；网页只复用导航内容，不能绘制假的 macOS 窗口按钮。移动端使用同一设计语义，但由触屏组件实现，不直接复用网页 DOM。

### 开放注册后的身份与费用边界

所有平台先取得账户会话，再以当前账户和项目权限调用 API。项目、素材对象、预览地址、AgentRun、事件流、操作确认和费用记录都按账户所有权检查；不能只在前端隐藏其他人的项目。首版每个项目只有一个所有者，不支持团队成员共享。开放注册至少需要验证、请求频率与上传容量限制，避免匿名占用存储或发起无限量任务。

Agent 模型和可灵供应商密钥由平台后台统一保管，所有客户端都不能读取或上传这些密钥。服务端从部署环境的秘密配置取密钥，调用时绑定账户、项目、运行与操作记录；密钥不写入数据库中的项目内容、事件日志或响应体。现有桌面 `.env.local` 密钥不会随项目同步自动上传，新的生成统一走后台。

演示版不接真实充值、支付或平台向用户收费。每个账户有可配置的生成次数／预算上限，服务端在创建付费操作前原子检查并预留额度；成功后结算，明确失败时按供应商实际计费情况释放或结算，`unknown` 状态保留预留直到核对。系统同时限制注册、上传和请求频率。确认界面告知“将消耗一次演示额度并调用后台生成服务”，后台记录实际供应商成本供演示和排查。额度控制不能只靠前端按钮禁用。若将来正式对外收费，再单独设计支付、退款和账单。

## 目标仓库边界

```text
apps/desktop       Tauri 壳、本地缓存与导出、共享 Web UI、插件宿主
apps/web           浏览器宿主、共享 Web UI、画布插件
apps/mobile        触屏宿主，不依赖画布包
apps/api           身份、项目同步、素材、AgentRun、事件与任务 API
packages/project-core   跨端项目领域规则与版本迁移
packages/agent-core     计划、步骤、工具权限与运行状态契约
packages/plugin-sdk     平台能力、UI／工具注入和插件数据迁移契约
packages/platform-ports 文件、媒体、任务、同步等平台端口
packages/design-tokens C4／青蓝语义变量
packages/ui-web        桌面／网页共用组件
packages/ui-native     移动端触屏组件（需要时建立）
plugins/canvas         桌面／网页画布、图数据与节点 UI
plugins/generation     生成工具与结果 UI，调用统一任务 API
```

API 与后台 worker 可先作为同一个可部署服务里的两个模块，保留清晰队列／数据库边界；有规模需求时再独立部署。不为首版建设任意插件市场或微服务群。

## 建议实施顺序与验收

1. **整理共享层**：把 C4／青蓝样式变为应用语义变量，提取桌面与网页都需要的组件；拆分 `studio` 中的领域数据与画布图数据，扩展静态插件契约。原桌面项目仍可打开。
2. **建立多账户云项目与运行账本**：注册登录、项目所有权、素材隔离、演示额度、资源版本、AgentRun／RunEvent／Operation 表、确认与恢复规则；后台配置平台密钥，先将桌面新生成切到同一云端任务 API，验证超时后不重复付费 POST。
3. **完成首个 Agent 闭环、自动同步与网页端**：照片上传、选集、确认、生成、结果归集；已有本地项目首次迁移、断网队列、显式冲突处理；网页打开同一项目、分集和任务，刷新后接回原运行。
4. **注入画布插件**：桌面和网页共用图数据及节点交互；卸载插件或从移动端访问后，分集内容和结果仍完整。
5. **移动端轻量入口**：输入、确认、运行状态、分集和结果；确保打包中没有画布依赖与节点 UI。

验收以两个注册账户和一个真实项目为准：账户 A 在桌面上传照片、选择分集并经 Agent 生成，网页看到同一 `runId`、逐步状态和该集的视频结果；账户 B 无法读到 A 的项目、素材或任务，任何客户端都读不到后台密钥。账户超过演示额度不能生成，`unknown` 任务不会因重试重复扣额度或再次提交供应商。断线恢复后没有第二次供应商提交；网页修改分集，桌面自动收到；两端并发改同一分集会暂停并要求选择版本；移动端能看结果但没有画布；旧本地项目和原有媒体文件仍可打开，但未登录时无法发起新的生成。

## 待用户审阅的取舍

本稿按“同一项目自动同步”建议**云端项目为权威、桌面为本地缓存**。这意味着已有本地项目需要一次可见的云关联与素材上传；之后才自动同步。若桌面完全不上传原素材，网页将无法直接使用这些素材生成或预览。平台后台持有供应商密钥、按账户发放演示额度已确定；正式商业计费不在本次面试演示范围内。

用户已选择首个 Agent 闭环完成到“照片生成视频并加入分集”、网页端开放注册、桌面端新生成全部登录并走云端。用户进一步明确这是面试演示项目：平台后台统一保存模型与可灵密钥，给注册账户演示额度，不做真实充值收费。数据库、队列、注册验证方式和前端具体库由实施者在计划阶段决定。旧项目首次上云应保留原文件并显示上传与冲突状态；这是本稿为避免数据丢失所做的设计选择，请用户审阅。
