# 网页端左侧导航交互修正

日期：2026-10-29。依据：用户指出左侧“首页／创作／画布／结果／资产”不能自由切换，并要求设计、前端修改和测试复测。用户确认无项目时采用对应页签空状态。

## 问题

`apps/web/src/App.tsx` 在无项目时把所有内容强制渲染为 `ProjectHome`，并把侧栏选中态强制设成首页；“资产”仅打开遮罩弹窗。这使按钮表面可点击，却没有对应的页面切换。

## 方案取舍

| 路线 | 结果 |
| --- | --- |
| 无项目时禁用其他页签 | 操作诚实，但用户无法浏览功能，也不符合自由切换的反馈。 |
| 无项目时都跳到项目库 | 路径短，但每个页签失去语义，仍像没有切换成功。 |
| **各页签始终可进入；无项目时显示对应空状态** | 点击结果与页签一致，明确下一步。采用此路线。 |

## 交互

1. 五个现有导航项始终可点击。点击后，侧栏 `aria-current` 与当前主内容一致；首页可随时返回，灵感草案保留。
2. 没有打开项目时，创作、画布、结果、资产分别显示有针对性的空状态与“选择项目／新建项目”入口。入口去独立项目库或显式新建弹窗，不暗中创建项目。
3. 已打开项目时，创作、画布、结果和资产均显示相应完整页面。资产页在主内容区展示项目素材；编辑器里的选素材弹窗可保留。
4. 在项目库、选项目、准备镜头等流程子页，侧栏不伪装成首页选中。用户切走后草案、已选提示词、分集和照片保留，返回时可继续；不会因导航产生视频任务。
5. `hasCanvas` 不可用时画布显示明确不可用状态，避免空白页；已有视频生成和审批规则保持不变。

## 验收

网页端分别在无项目、有项目两种状态点击五个导航项，主标题和选中态都正确；资产显示主页面；切到首页再回来仍保留灵感输入；任何导航切换都不创建项目或视频任务。测试同时覆盖键盘焦点与 `aria-current`。截图来自真实网页客户端。
