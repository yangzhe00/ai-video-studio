# AI Video Studio 多端与插件架构设计

日期：2026-10-27。状态：架构设计草案，尚未实施。

## 目标与范围

将当前 macOS Tauri + React 单应用逐步演进为同一仓库内的桌面、网页和 iOS/Android 移动应用。三端共用项目规则、功能契约、Agent 工具定义及设计规范，按平台选择启用功能。桌面端已有的本地导入、顺序剪辑、字幕、文案、分镜草稿、费用估算和本地导出应在迁移期间持续可用。

移动端首版定位为项目查看、分镜、轻量剪辑及生成任务管理。完整本地多轨剪辑与导出不作为首版承诺。网页端优先支持项目查看、故事板、字幕和文案；云素材、生成和导出需要服务端能力。生成视频和口型同步仍需真实模型服务，Agent/MCP 不替代模型。

## 已确认的取舍

| 议题 | 选择 | 原因与边界 |
| --- | --- | --- |
| 仓库组织 | pnpm workspace 单仓库 | 现有项目已用 pnpm，内部包用 `workspace:` 引用；先不引入第二层构建编排器。 |
| 桌面端 | 保留 Tauri 2 + React | 避免重写已可用的本地文件和 FFmpeg 路径。 |
| 网页端 | React 应用 + 服务端 API | 复用 Web 组件，浏览器不能直接使用 Tauri 命令或 macOS 钥匙串。 |
| 移动端 | 优先评估 Expo / React Native | 共用纯业务包与设计 tokens，针对触屏重新组合界面；Tauri mobile 保留为成本对照和验证选项。 |
| 插件 | 仓库内编译期选择的功能模块 | 首版不加载未知第三方运行时代码，避免权限、兼容与发布负担。 |
| MCP | 内部工具契约先行，MCP 作为外部适配层 | 三端共用同一业务动作，不让协议反向决定编辑器的数据模型。 |

## 方案比较

1. **单应用继续增量开发**：迁移成本最低，但 Tauri 调用和页面状态继续混在一起，未来网页与移动端会复制业务逻辑。
2. **立即全面拆为微服务与动态插件平台**：扩展能力强，但需要大量尚无用户需求的部署、版本和权限设施，演示项目的复杂度与费用过高。
3. **渐进式 monorepo + 静态插件 + 平台适配器（采用）**：先保住桌面功能，再抽出纯业务规则，最后新增网页和移动应用。增加少量包边界管理成本，换来可检查的复用关系。

## 目标目录及依赖方向

```text
apps/
  desktop/             当前 React 前端与 src-tauri，负责 macOS 本地能力
  web/                 浏览器应用，调用后端 API
  mobile/              Expo/React Native，首版轻量编辑
  api/                 账户、云项目、素材、AI 任务、密钥及云端导出
packages/
  project-core/        项目 schema、版本迁移、时间线操作、校验、撤销命令
  plugin-sdk/          插件 manifest、能力声明、注册和宿主接口
  platform-ports/      文件、媒体、渲染、密钥、任务、持久化抽象
  design-tokens/       颜色、字体、间距、动效和图标语义
  ui-web/              桌面与网页共用的 Web React 基础组件
  ui-native/           按同一 tokens 实现的触屏组件
  agent-core/          操作计划、工具目录、确认和执行审计
plugins/
  media/ timeline/ captions/ cover/ publishing/
  storyboard/ image-to-video/ lip-sync/ export/ assistant/
```

依赖方向为 `apps → plugins → project-core / platform-ports / UI 包`。功能插件之间不直接读写彼此状态；跨功能变更由 `project-core` 的业务命令处理。React 组件不得直接调用 Tauri 命令或云 API，而是通过宿主注入的端口接口调用。Rust 模块和 FFmpeg 二进制只留在桌面适配器；网页与移动端不依赖它们。

## 数据与项目边界

- `ProjectManifestV2` 是现有桌面项目格式。迁移时先抽出 TypeScript 类型与校验，保持磁盘格式兼容；新增字段必须有版本迁移和旧项目打开验证。
- 设计可移植的下一版资产引用为带类型的 `localRelative` / `cloudObject` / `remoteGenerated`，保留稳定素材 ID。桌面 V2 项目读取时经适配器映射为领域对象；仅在用户明确执行项目升级或云端上传时写出新格式。云端上传先复制素材并取得对象引用，再提交新 manifest；失败时不改原本地项目。
- 片段、素材、字幕、分镜和任务以稳定 ID 引用。时间线编辑统一走命令，命令包含参数校验、目标项目 ID、预期 revision 及撤销所需的变更记录。
- `schemaVersion` 与 `revision` 分开：前者用于格式迁移，后者每次成功提交递增。桌面适配器以当前 revision 检查后将整个新 manifest 原子写入临时文件并替换旧文件；云端适配器使用服务端事务或条件更新。Agent 一次确认的纯元数据操作先在副本上全部验证，再作为单次提交落盘；任一步失败都不写入。撤销保存该次提交的前一版元数据快照，并同样做 revision 检查。素材导入、视频导出和付费任务不包含在此可撤销批次中。
- 桌面项目仍对应一个独立本地目录。网页与移动端使用云项目 ID、对象存储素材引用和服务端权限，不把桌面的绝对路径同步到云端。跨端同步为后续独立阶段；首版不声称本地项目自动同步。
- 素材缺失、上传中、生成中、远端任务状态未知是显式状态。远端提交结果不确定时先查询任务，不自动重复扣费提交。

## 插件契约

每个功能插件声明 `id`、版本、依赖能力、支持的平台、提供的导航入口/面板、业务命令、Agent 工具、权限需求与迁移要求。宿主在启动时注册允许的插件，并进行依赖与平台检查；不支持的平台显示解释性状态或隐藏入口。插件负责自己的 UI 和功能适配，项目 schema、权限策略、保存与撤销由核心统一管理。

首轮插件划分以用户可独立理解的能力为界：素材、时间线、字幕、封面、发布文案、分镜、图生视频、口型、导出、助手。`image-to-video`、`lip-sync` 在有真实供应商接入前只提供草稿与费用规划，不注册可执行的生成工具。插件可以按端选择：例如桌面启用本地导出，网页启用云端导出，移动端首版只显示导出任务和结果。

## 设计系统与界面复用

沿用已确认的故事板＋时间线双视图。`design-tokens` 提供色彩、文字层级、空间、焦点和状态语义；`ui-web` 提供按钮、输入、对话框、素材卡、状态徽标等可复用组件。移动端共用 tokens 和业务状态，但用 `ui-native` 重新排布工作台和触控操作，不直接移植桌面三栏布局。组件库只包含通用控件与呈现组件，具体剪辑行为仍在功能插件和核心命令中。

## Agent、工具与 MCP

Agent harness 负责接收意图、读取项目快照、选择工具、生成操作计划、展示差异、等待确认、执行、记录结果和失败恢复。工具返回结构化结果，不允许模型直接写项目文件。首版工具集：读取项目摘要和素材、读取时间线、草拟片段排序与裁剪、添加或修改字幕、保存发布文案、创建分镜草稿、费用预估。导出和付费生成属于单独确认动作；任意 shell、任意路径读写不进入工具目录。

首个演示闭环：用户说“保留开头 3 秒，把说话片段放到做饭片段后，并加这句字幕”；助手展示变更前后顺序、裁剪范围和字幕绝对时间；用户确认后提交一组可撤销命令，预览和项目文件同步更新。Agent 可使用支持函数工具调用的低成本模型；没有模型密钥时保留手动编辑和确定性工具。未来以 MCP server 适配同一工具目录，供外部 Agent 连接；应用内部不因 MCP 而引入第二套编辑实现。

首版外部 MCP 仅考虑桌面本机 stdio：用户在应用中明确启用，并选择一个项目及允许的工具范围后，宿主发放短期会话能力；MCP 适配器不能枚举其他项目或接受任意路径。只读工具可直接返回，修改工具只能提交操作计划，必须回到桌面应用由用户确认后才执行。付费生成和密钥管理不向外部 MCP 暴露。远程 HTTP MCP、第三方插件安装及跨账户访问留待独立的身份与权限设计。

## 安全、费用和可观测性

- 桌面密钥继续使用 macOS 钥匙串；网页和移动端供应商密钥由服务端保管，客户端不得持有共享的服务端密钥。个人自带密钥需要独立评审安全与计费边界。
- 工具通过当前项目 ID、素材 ID 和权限范围定位对象；服务端再做身份和项目授权检查。插件权限按功能最小化，所有付费提交都需要明确费用上限。
- 记录操作计划 ID、工具名、输入摘要、项目版本、结果和外部任务 ID；日志不记录密钥或完整私人素材内容。提交状态不明时标记 `unknown` 并查询远端，不盲目重试。
- AI 推理和视频生成分别计费。Agent 可辅助决策，不代表图生视频和口型能力免费或已实现。导出是否本地或云端由平台适配器明确告知用户。

## 分阶段实施与验收

1. **仓库迁移**：建立 workspace 和 `apps/desktop`，保持 `pnpm` 启动、测试、Tauri 启动及真实素材导出结果不变。
2. **核心抽取**：项目类型、时间线命令与校验迁入 `project-core`；旧 `ProjectManifestV2` 项目可打开、编辑、保存与导出。
3. **设计系统和静态插件**：实施双视图 UI；插件按桌面能力注册，空状态、缺失素材和未生成状态准确。
4. **Agent 首闭环**：只读工具、操作计划、确认、批量执行与撤销；验证失败回滚，不接入付费生成。
5. **网页端**：网页查看和轻编辑、API 与云素材；验证浏览器无法触达桌面文件和钥匙串。
6. **移动端**：查看、分镜、轻量剪辑、任务状态；用真实设备验证触控与媒体预览。
7. **MCP 与生成插件**：在工具与授权模型稳定后暴露 MCP；独立接入图生视频及口型供应商，并验证费用、远端未知状态和结果回收。

每阶段交付可运行版本和针对其核心风险的验收结果。新增网页与移动端前先做各平台素材、预览、密钥和导出能力的技术验证；若 Expo 媒体能力达不到目标，再对照 Tauri mobile 或原生模块调整移动端方案。
