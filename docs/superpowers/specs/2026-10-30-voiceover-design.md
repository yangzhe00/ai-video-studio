# Voiceover Design — 2026-10-30

## Intent

给现有无声或有声视频增加可试听、可调整、可导出的配音。用户已确认第一版有两个入口：上传自己的录音；输入文字，调用可灵 TTS 生成录音。配音可放在单个镜头或整集，均不改变人物或宠物口型。本轮不开发对口型。

## User flow

1. 在镜头微调或分集时间线选择「添加配音」，选择上传录音或文字生成。
2. 上传录音后校验真实媒体格式、时长和归属。文字生成前展示声音、文案、实际费用由可灵按用量扣除的提示与再次确认入口；服务端创建可恢复的 TTS 任务，完成后将结果保存为 `voice` 资产。官方接口未提供事前确定报价，不展示虚构预估金额。
3. 用户试听，调整开始位置、截取范围和人声音量，并分别调整原声与背景音乐音量；保存草稿不启动付费任务或导出。
4. 用户确认导出；镜头微调生成新视频版本，整集导出生成独立成片。原片和旧版本可继续访问。失败后给出任务状态与安全重试入口。

## Data and rendering boundaries

- `packages/project-schema` 的 `VoiceAsset`、`VoiceClip` 和 `voice` 轨道表达素材及分集时间位置；`@ai-video/api-contracts` 统一请求、响应、错误码。旧项目和 `VideoEditRecipeV1` 必须能读取；新增配方按版本演进，不修改旧配方的含义。
- 镜头配音时间以保留片段为基准。分集配音时间以分集时间线为基准。所有剪裁、混音和导出都读取已确认的资产 ID，不让客户端传任意文件路径或 FFmpeg 命令。
- 服务器 FFmpeg 负责原声、配音和音乐的混音、截断与音量控制；要验证输出实际有 AAC 音轨。桌面本地导出遵守同一时间与音量语义。
- TTS 密钥仅在服务端，记录供应商任务 ID 和费用状态。超时或响应丢失后先查询已有任务，避免再次付费提交。TTS 生成完成不自动触发视频渲染。
- 云端现有渲染仅处理单镜头；为兑现网页端的「整集配音后导出」，需要增加读取分集 DSL 轨道的云端整集导出。不能把桌面本地导出视为网页端已经具备该能力。

## Acceptance

- 上传 MP3/WAV/M4A 中实际支持的格式，并用 `ffprobe` 复核。损坏文件、超限文件、跨账号资产、音频短于/长于镜头、无声和有声原片均有明确结果。
- 新生成视频第一版固定 5 秒（当前可灵 2.5 Turbo 只支持 5/10 秒，5 秒满足用户提出的单条 3–5 秒上限）；旧 10 秒项目仍可读取、配音和导出。镜头可设置配音位置和音量，合成预览与正式导出使用同一混音配方；分集跨两个镜头的配音不断裂，原声和背景音乐音量可控。
- 文字生成音频可试听、复用，不重复付费；供应商不可达或权限不足时给出可操作错误，上传录音入口仍可使用。
- 导出失败保留原片和上一成功版本；重复确认同一配方版本不生成第二个成片或第二笔 TTS 任务。
- Web 与桌面实际页面、导出 MP4、`ffprobe` 音轨检查及关键状态截图作为验收证据。移动端遵守共享 API 和 DSL，但本轮以网页与桌面成片闭环为上线门槛。

## Approach chosen

复用现有三层 DSL、云端版本化渲染和桌面 FFmpeg 导出，增加语音资产及音轨执行。上传音频与可灵 TTS 都产出相同 `voice` 资产，由同一预览和导出链路消费；预览产物短期保存并可过期清理，不为两个入口分别实现媒体处理。用户在 2026-10-30 明确同意这两条入口、文字配音线上实际提交和单条视频 3–5 秒限制，并将对口型移出本轮。
