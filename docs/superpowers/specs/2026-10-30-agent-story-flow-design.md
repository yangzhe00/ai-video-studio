# Agent 主导 15 秒微故事：产品设计稿（待用户审核）

日期：2026-10-30。身份：产品经理。阶段：**产品方案**，不代表架构、代码或线上能力已完成。交互细节与验收见 [PRD](../../product/2026-10-30-agent-story-flow-prd.md)，可点击演示见 `design/prototypes/agent-story-flow/index.html`。

## 意图与用户

定位句由用户选择：**“说出一个念头，让 Agent 把它拍成故事。从创意、分镜到视频片段，Agent 主导推进；你在关键步骤选择和确认。”** 主要用户是没有脚本、不会操作节点画布、想发布一条完整短视频的新手。已有剧本的用户仍能保留原文并进入同一故事流程。要解决的是空白画布不知从何开始、生成片段彼此无关、费用与进度不可预期。

## 现状与边界

- 当前文字 Agent 的三版是**同一单镜头**的提示词；线上真实请求曾最终 `provider_error`、0 版。不得把现有三版说成三篇故事。
- 云端新视频固定 5 秒、需要参考图，默认每账号 3 次演示额度；当前不存在“只说一句话、无照片、自动连续拍三镜”的完整链路。
- 当前画布一集一张，视频节点逐个手动执行，结果可入时间线。桌面和网页有画布；移动端不加载画布编辑器。
- 首发宣传不承诺真实生成速度、售价或成功率，直到端到端实测与账单核对通过。

## 方案比较与选定建议

| 方案 | 用户操作 | 优点 | 代价 |
| --- | --- | --- | --- |
| A. 继续只给三版单镜头提示词 | 用户逐镜头构思并进画布 | 复用当前实现 | 不符合“Agent 把念头拍成故事” |
| **B. 15 秒三镜头微故事，Agent 自动建分镜并在总授权内拍摄** | 选故事、审分镜、确认费用；可选画布精修 | 最短能呈现起因、变化、结果；与现有 5 秒镜头和演示额度接近 | 需新增故事规划、无照片参考、预算及多任务编排 |
| C. 首发 60 秒短片 | 一次产出更多情节 | 宣传更直观 | 12 个镜头放大失败率、成本、人物一致性和等待时间风险 |

**产品经理推荐 B**。用户上一轮认可 Agent 新能力和量化验收方向；本设计把 15 秒作为首发可验收的“微故事”，30 秒作为扩展故事，约 60 秒及以上才称“短片”。如果用户调整时长或价格，以新的审核意见为准。

## 主流程与体验取舍

一处输入框、两个动作：**让 Agent 拍成故事**与**用我的内容开始**。前者由 Agent 给 3 个完整故事方向；后者保留原文并进入作品设置。单镜头功能留在创作页，不把“3 条单镜头提示词”假装为完整故事。所选故事创建或加入明确项目和分集，Agent 在该分集画布上形成 3 个可编辑分镜及时间线。小白首先看线性“故事预览”，画布是“打开画布精修”的可选高级视图。

用户的三次关键决定为：选故事、确认分镜、按列明的三个 5 秒镜头与总费用上限确认拍摄。一次总确认仅授权当前分镜版本中的三项付费任务；超额、新增镜头或主动重做须再次报价。进入页面、保存文本、连线、生成参考图草案与预览不自动扣视频费用。供应商任务状态不明时查询原编号，不重发。

无照片是主路径，因此 Agent 必须自动准备有一致角色/风格的视觉参考，并允许用户用自己的照片替换。此能力在架构评审中比较“文本直生视频”与“角色锚图+分镜参考图”；上线验收须验证没有照片也能完成 15 秒故事，不能把用户补图作为隐含前提。故事版本、提示词、参考图、任务编号、结果与时间线选择都需持久化，旧片不可被重做结果静默覆盖。

## 上线前量化门槛

用户主动操作时间中位数 ≤90 秒（24 名初次用户）；确认到可播放 15 秒初稿 P50 ≤10 分钟、P90 ≤20 分钟（至少 100 次真实任务）；三段情节可辨认率 ≥80%（至少 30 个题材、3 名盲评）；形成可播放初稿比例 ≥95%；断线/重复点击重复付费提交为 0。公开售价 `¥39.9/15 秒` 仅是**内测待验证目标**，必须拿真实供应商账单及完整可变成本核算，不能直接发布。官网与 GitHub README 的数字必须由同一验收记录解锁，并标明统计口径。

## 发布顺序与审核闸门

P0 修复真实文字 Agent、选定并打通无照片参考能力、获得实际供应商费用；P1 打通 15 秒故事端到端；P2 依据真实数据优化一致性并扩展 30 秒，后续再评估 60 秒。架构会话先提交可审阅的架构方案与拆分建议，**用户审核通过后**再派给前端、后端和测试会话开发；测试最后以同一项目/故事运行编号完成关键词→创意→画布分镜→拍摄→成片全链路，交付截图。产品方案与原型均不代表真实功能已实现。
