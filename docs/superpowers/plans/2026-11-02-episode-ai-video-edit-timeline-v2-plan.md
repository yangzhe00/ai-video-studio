# 整集剪辑 v2 开发分工与集成顺序

日期：2026-11-02。输入：`docs/product/2026-11-02-episode-ai-video-edit-timeline-v2.md`、`design/prototypes/episode-ai-video-edit-v2/index.html`、`docs/acceptance/2026-11-02-episode-ai-video-edit-timeline-v2-test-scope.md`。

1. **后端与架构先对齐能力/契约**：核实生产供应商能否接收源视频、标注帧/参考图和文字并真实返回受控新视频，给出官方能力文档、费用/限额及不支持分支；确定报价、提交、查任务、应用结果的共享契约和稳定幂等键。若不能实现局部视频编辑，明确阻塞，不用普通文生视频冒充。设计旧数据兼容和无迁移/有迁移方案。前端并行实现纯 UI 与本地时间尺交互。
2. **后端实现**：鉴权和资产校验、服务端抽帧与标注合成、任务输入快照、费用确认、供应商适配、operation 持久化/断线恢复、结果资产登记、按分集修订原子替换、冲突及失败恢复。限定一次任务一个镜头；保留源片/旧成片。
3. **前端实现**：共享整集组件重排时间线；稳定轨名、缩略帧、波形、时间尺 Pointer Events 拖动/键盘/缩放/滚动；AI 工作台的帧选择、框选/文字/点、参考图/提示词、报价二次确认、任务恢复、原新片播放、只存候选/替换；Web 和桌面接同一契约。旧多轨编辑不可回退。
4. **集成与审查**：前后端先跑共享契约/单元/隔离 API，再 Web 和原生冷启动；代码审查关注真实 provider、计费幂等、帧坐标、版本冲突、音轨保留和既有时间线回归。给测试一个固定候选版本，不能一边测一边无记录改代码。
5. **测试会话独立验收**：按 E01–E09 跑完整闭环，先取真实截图与任务/视频证据；失败项由开发修复后在新候选重测；最终直接向用户交报告与截图。原型截图只说明设计，不算验收。

并行边界：前端可先做时间线外观、尺拖动、标注组件和假数据下的 UI 测试；后端未提供真实 provider 和任务契约前，任何“AI 成功”均不能称完成。用户要求的是实际视频编辑能力及真实验收截图。
