# Agent 主导 15 秒微故事 Implementation Plan

> **For agentic workers:** 各会话按本计划的依赖顺序执行；每项以 `- [ ]` 跟踪。前后端采用现有会话实施，架构定接口，测试独立验收，代码审查最后执行。

**Goal:** 用户从一句关键词选择三篇故事中的一篇，由 Agent 在同一集画布形成三镜分镜，用户批准三次 5 秒拍摄后获得可播放、可导出的 15 秒微故事。

**Architecture:** 架构会话先定故事/分镜/报价/运行的契约和无照片路径。后端负责真实文字与视频任务、费用边界及恢复；前端使用同一故事数据呈现引导视图和画布；测试用同一 `storyId/runId` 贯穿真实链路。

**Tech Stack:** 仓库现有 TypeScript、React（网页/桌面）、React Native（移动）、Tauri、Node API、PostgreSQL、项目 DSL 与画布插件。具体模型/供应商由架构方案选定。

**Spec:** [完整 PRD](../../product/2026-10-30-agent-story-flow-prd.md)；[交互原型](../../../design/prototypes/agent-story-flow/index.html)；[设计取舍](../specs/2026-10-30-agent-story-flow-design.md)。

## Global Constraints

- P0 先恢复线上真实文字 Agent，不允许用模拟故事通过验收。
- 新 `StoryIdeaSet` 是三篇完整故事；当前 `PromptIdeaSet` 是同一单镜头的三版提示词，两者不可混用。
- P1 标准初稿是 3 × 5 秒、同一项目/分集/画布与时间线，导出时长目标 15±0.5 秒。
- 视频请求前必须展示有效报价和总上限，由用户明确确认；提交意图先持久化，未知状态先查原任务。
- 无照片关键词路径必须可用。用户原文与已生成片段不可被自动改写覆盖。
- 旧单镜头、手动画布和旧项目保持可用；移动端使用线性分镜视图，不要求画布编辑。
- 90 秒、10 分钟、¥39.9 都是待验证目标；官网与 GitHub README 不得发布成已实现事实。
- 当前工作区有其他会话在改 API、网页、桌面、移动和数据库；各会话开始前检查最新工作区，禁止覆盖他人未完成的变更，先与架构明确接口和文件边界。

## Review Focus

1. 无照片输入：三篇故事可生成，但没有可用视觉参考时拍摄确认必须禁用；后端和前端都要覆盖。
2. 响应丢失/重复点击：相同确认 ID 只形成一组批准的三镜任务；后端故障注入与前端恢复测试都要覆盖。
3. 分镜编辑后旧报价失效：服务端校验修订哈希，前端强制重新查看价格。
4. 一镜失败：另外两镜保留，不能称为 15 秒成片；查询原任务后才可单镜重新报价。
5. 桌面未登录/跨账号：本地草稿不自动声称网页同步；云端故事不可泄露给另一账号。

## 任务与依赖

### Task A · 架构：先冻结跨端契约（P0）

**Owner:** 架构会话。**输入:** PRD 第 1–6、8–10 节及 HTML 原型。**产出:** `docs/architecture/2026-10-30-agent-story-flow-architecture.md`，并标注 P0/P1 接口冻结版本。

- [ ] 核对当前线上 `provider_error`、现有 `apps/api/src/prompt-ideas.ts` 与 `idea-agent-worker.ts` 的责任边界，给出定位和修复路径。
- [ ] 比较无照片方案（文生视频或 Agent 准备参考图）与真实供应商能力、单价、角色一致性风险；选择 P1 路径和降级方案。
- [ ] 定义 `StoryIdeaSet`、`StoryPlan`、`ShotReference`、`StoryQuote`、`StoryRun`、`StoryResult` 的字段、所有权、API、事件序号和状态机；列明与现有项目 DSL/分集/画布/时间线的映射。
- [ ] 定义三镜总确认与分镜修订哈希、额度/费用上限、提交意图、幂等、断线、部分失败、单镜重做及导出事务的边界。
- [ ] 给出数据库迁移/回滚、跨端兼容、可观测性、服务健康、任务队列和供应商限流方案；明确前后端文件/接口边界。
- [ ] 将方案交产品/用户评审并在共享文档记录结论；**接口未冻结前，前端不得把模拟数据接成真实拍摄，后端不得让新视频端点上线。**

### Task B · 后端：真实文字 Agent 与无照片前置能力（P0）

**Owner:** 后端会话。**Dependency:** Task A 中的文字契约；线上 `provider_error` 排查可先独立启动。**Files to inspect:** `apps/api/src/prompt-ideas.ts`、`idea-agent-worker.ts`、`idea-agents.ts`、`server.ts`、`config.ts` 及相关测试；新文件名按架构接口定稿。

- [ ] 写可复现的公网故障记录：请求 ID、认证/配置/供应商响应、错误码和现网部署版本，脱敏保存；定位 `provider_error` 真正原因。
- [ ] 修复真实文字调用并用独立账号验证；结构化输出恰好 3 篇**完整故事**，分别有起因/变化/结果，拒绝空白模板、重复方案和引用不存在照片。
- [ ] 保留现有单镜头三版提示词接口与行为；故事请求可查询、可恢复、重试不产生视频任务。
- [ ] 完成架构选定的无照片参考/生成路径与报价数据来源验证；未知单价不返回 0 元可拍报价。
- [ ] 运行对应 API 单测、集成测试及一次真实模型 smoke；记录输入、输出结构、调用链、费用、失败样例和版本。

### Task C · 后端：故事拍摄与成片编排（P1）

**Owner:** 后端会话。**Dependency:** Task A 接口冻结、Task B 真实文字/无照片路径通过。**Files to inspect:** `apps/api/src/runs.ts`、`generation-worker.ts`、`render-worker.ts`、`cloud-document.ts`、`db.ts`、项目/时间线 DSL 与相关测试；新增文件按架构分层。

- [ ] 持久化原文、故事选择、三镜分镜及修订；自动创建一集的画布/时间线目标数据，旧项目可读取。
- [ ] 服务端为当前修订返回三项 5 秒明细及总上限；确认时校验账号、项目/分集、参考、额度、报价有效期与修订哈希。
- [ ] 先落库三条提交意图再调供应商；相同确认 ID 幂等，供应商响应未知时查询原任务，不重复 POST。
- [ ] 三镜成功按序自动装配；失败保留成功片段，单镜重做另报价且留旧片；导出 MP4 可重试同一渲染任务。
- [ ] 测试并记录：重复确认 0 重复提交、断线恢复、报价过期、部分失败、原片保留、导出时长 15±0.5 秒、跨账号拒绝。

### Task D · 前端：一个输入到画布分镜（P1）

**Owner:** 前端会话。**Dependency:** Task A 接口冻结；可先做不触发收费的页面/状态骨架。**Files to inspect:** `packages/components/src/ProjectHome.tsx`、`packages/ui-web/src/PromptIdeas.tsx`、`apps/web/src/App.tsx`、`apps/desktop/src/App.tsx`、`plugins/canvas/src/CanvasPage.tsx`、`apps/mobile/src/App.tsx`。优先复用现有组件，不在三端复制三套业务状态。

- [ ] 按原型实现首页一个输入框两个动作、三篇完整故事的选择/编辑、项目/分集归属；保持现有单镜头模式入口。
- [ ] 实现默认线性三镜分镜与同源画布节点状态；编辑、重新规划、替换参考、返回选故事均保留原文且使旧报价失效。
- [ ] 接入服务器故事/分镜状态；加载、空、配置错误、失败、未登录、断网和无照片参考失败均有明确下一步。
- [ ] 网页和桌面可打开画布精修；移动只显示线性分镜并引导到网页/桌面精修。
- [ ] 用组件/交互测试验证 3 篇而非 3 个单镜提示词、无项目空态、键盘/窄屏、跨账号与草稿恢复；提交真实运行截图。

### Task E · 前端：报价、进度、成片（P1）

**Owner:** 前端会话。**Dependency:** Task C 的报价/运行/结果 API。**Files:** Task D 的相应视图、API 适配器与组件测试。

- [ ] 展示三镜明细、总上限和有效期；价格未知/额度不足/参考缺失/修订变化时禁用“确认拍摄 3 个镜头”。
- [ ] 一次确认只绑定当前分镜修订；重复点击、刷新、跨端打开查询同一 `runId`。
- [ ] 显示每镜实际状态，状态未知不伪造成功/失败；一镜失败只给查询或单镜重新报价入口。
- [ ] 成功初稿可播放、画布精修、只重做一镜、看账单/任务与导出 MP4；旧片和旧导出不被自动覆盖。
- [ ] 用真实 API 候选环境做网页、桌面、移动相应路径的交互核验；提交截图及测试结果。

### Task F · 测试：独立验收与截图（P0/P1）

**Owner:** 测试会话。**Dependency:** 用例设计立即开始；真实全链路等 B–E 合并到同一候选版本。**Output:** `docs/acceptance/2026-10-30-agent-story-flow.md` 与同名 `evidence/` 截图、任务记录。

- [ ] 按 PRD 第 9 节写测试矩阵与环境、账号、真实供应商、费用上限、同一 `storyId/runId` 的取证方法；先验证 P0 `provider_error` 真正恢复。
- [ ] 从关键词 → 真实三篇故事 → 选择 → 自动画布三镜 → 费用确认 → 三镜拍摄 → 时间线 → 15 秒 MP4 导出，逐步收集 E01–E10 截图/录屏、元数据和真实费用记录。
- [ ] 覆盖五项 Review Focus 及空、错、载、断网、刷新、重复点击、额度、报价过期、单镜失败、导出失败；每项记录通过/失败/阻塞。
- [ ] 仅在真实可用版本上量化故事连贯性、主动操作时间和渲染时长；保留原始分母与失败样本，不能以模拟数据解锁官网数字。
- [ ] 把完整报告和截图交产品负责人审核；失败项返回对应前后端会话修复、复测后再交代码审查。

### Task G · 代码审查与公开文案（P1 发布闸门）

**Owner:** 代码审查会话；官网/README 修改由对应开发会话按审查结果实施。**Dependency:** Task F 已有真实全链路报告。

- [ ] 审查同一候选版本的权限、幂等、费用上限、数据迁移、旧流程回归、画布/时间线一致性、跨端与错误恢复。
- [ ] 严重问题修复并由测试复验；无真实证据不得勾选通过。
- [ ] 官网 `apps/website/` 与 `README.md` 使用同一组已解锁的数字、条件、日期和样本量；未达到门槛的卡片不展示数值。
- [ ] 发布后做公网与下载/登录/真实故事链路复验，记录部署版本和回滚入口。
