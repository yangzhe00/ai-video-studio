# AI Video Studio 全局 UI 与交互原型交接

状态：产品经理交接规格，2026-10-28。基于当前 Pen 画板、主题 token、已确认产品决策和三端界面。设计稿与原型应展示目标体验；本文不代表所有目标状态均已在产品代码中实现。

## 1. 目标与交付边界

面试演示要让评审在一条可点通的路径中理解：**登录 → 输入照片和提示词 → Agent 给出计划 → 用户确认云端生成 → 实时查看任务 → 得到视频并微调 → 加入分集 → 桌面／网页画布编排整集**。桌面、网页、移动端使用同一云账号、项目、分集与任务；画布仅在桌面和网页出现。一个项目可有多集；一张画布制作一集。

本次需要两类设计交付：

1. **Pen 整体项目**：一套可复用的全局变量与组件，覆盖登录、首页、生成、画布、结果、微调入口，以及文末状态矩阵中的关键页面。默认 C4 奶油胶片，另有可一键切换的青蓝夜幕。当前 Pen 文件是继续扩展的基线，不另起孤立风格。
2. **Axure 交互原型**：用可点击页面、动态面板和变量模拟完整流程、分支与恢复；原型任务使用演示数据，不调用真实付费服务。交付时应有可编辑 `.rp` 源文件及浏览器可访问的预览或导出 HTML。

本机 `/Applications` 与 `~/Applications` 未发现 Axure RP，当前工具也没有 Axure 编辑接口；因此**本文是可直接绘制的 Axure 规格，尚不是 `.rp` 文件**。已提供 `design/interaction-clickthrough.html` 作为基于 Pen 截图的可点击走查件，便于先验证页面跳转与异常分支；它不替代 Axure 原生文件。Axure 官方文档说明桌面应用编辑 RP 文件、动态面板管理状态、交互事件驱动跳转，交付者需要在 Axure RP 中完成原生文件并预览核验： [安装](https://docs.axure.com/axure-rp/reference/installing-on-macos/)、[动态面板](https://docs.axure.com/axure-rp/reference/dynamic-panels/)、[交互事件](https://docs.axure.com/axure-rp/reference/events-cases-actions/)、[预览与分享](https://docs.axure.com/axure-rp/reference/viewing-sharing-prototypes/)。

## 3. 全局视觉系统

### 3.1 风格

- **C4 奶油胶片，默认**：奶油底、暖陶主色、柔和纸面与电影胶片意象；内容突出参考照片、提示词、任务和片段，不用大面积炫技光效盖住操作。主背景 `#F7F2EB`，面板 `#FFFCF8`，正文 `#2B2A26`，强调 `#B96C4A`，边框 `#D5C5B5`。
- **青蓝夜幕，第二套主题**：深灰底、冷青强调与高对比节点连线。主背景 `#0D0F12`，面板 `#23292C`，正文 `#F1F5F7`，强调 `#55CADD`，边框 `#3B4B51`。
- 两套主题使用同一布局、字号、组件、状态、信息层级与交互。全局主题只改视觉，不改输入、节点、时间线、任务或媒体。默认 C4；切换偏好持久化。旧的 A/B/C1–C3 方案继续留在 Pen 作为探索史，不出现在产品换肤菜单。

### 3.2 原子、语义与组件层级

代码基线 `packages/design-tokens/src/tokens.css` 已有 `cream-film` / `cyan-night` 语义变量，`packages/ui-web/src/ThemeProvider.tsx` 已有切换和本地持久化。Pen 主题轴使用 `skin`。Pen 设计和 Axure 小部件不得再复制一套独立颜色表，统一按以下层级命名：

| 层级 | 最小交付 | 例子 |
| --- | --- | --- |
| 基础原子 | 颜色、4px 间距基数、字阶、字重、圆角、边线、动效时间 | space-1/2/3/4/6/8、radius-sm/panel |
| 语义 token | 背景、侧栏、工具栏、面板、文本、边框、主色、成功／警告／失败、画布背景／连线、焦点 | `--avs-background`、`--avs-primary`、`--avs-canvas-connection` |
| 组件 | 窗口栏、导航页签、按钮、输入、上传框、结果卡、任务进度、节点、检查面板、时间线、弹窗、Toast、空态 | normal / hover / focus / disabled / busy / error |
| 页面模板 | 登录、首页、生成、画布、结果、微调 | 所有页面消费同一组件与 token |

桌面顶部原生窗口栏固定 48px、底色 `#E9EDEB`，页面内容从其下方开始；三色窗口控制由桌面壳提供，设计图圆点只是占位。网页没有假 macOS 窗口控制，可复用导航内容。移动端使用相同语义和品牌色，但以原生触控控件重排，不能照搬桌面画布。

### 3.3 动效与无障碍

首页与登录页 C 方案：胶片慢速移动、暖光扫过、薄雾漂移和微弱颗粒闪动；任务状态只允许轻量进度动画，不用循环动画掩盖真实状态。主题切换可短时淡入，不让媒体预览重载。`prefers-reduced-motion` 或系统“减少动态效果”开启后停止背景循环，仅保留静态层次。文字、图标、焦点边框在两套主题都要可读；成功／失败不可只凭颜色表达。

## 4. 信息架构与跨端入口

```text
未登录 → 登录 / 注册 → 项目首页 → 选择 / 创建项目
                                  ├─ 生成 → 任务计划 / 运行状态 → 结果 → 视频微调
                                  ├─ 分集 → 画布 → 视频节点 → 整集时间线 → 导出（桌面／网页）
                                  └─ 素材、人物、历史任务
```

| 能力 | 桌面 | 网页 | 移动 |
| --- | --- | --- | --- |
| 登录注册、云项目、照片／提示词生成、任务状态与结果 | 有 | 有 | 有 |
| 画布节点与整集时间线 | 有 | 有 | 不提供画布；从分集镜头列表查看结果 |
| 视频微调：首尾裁剪、字幕、封面 | 有 | 有 | 有，触控单列 |
| 本地缓存、离线编辑、详细本地剪辑与 MP4 导出 | 有 | 以云端能力为准 | 不提供本地详细剪辑 |
| 全局换肤 | 两套主题 | 两套主题 | 用相同语义色做触控主题；在移动设置页手动切换并保存在本机，原型需演示切换后返回结果页 |

## 5. 页面清单与状态画板

Pen 命名建议：`平台 / 页面 / 主题 / 状态`，如 `WEB / 生成 / cream-film / 生成中`。先用 1440×900 桌面基线制作，再给登录、首页、生成、结果、微调提供 390×844 移动视图；画布只做宽屏，窄窗显示“请在宽屏继续编辑”而非缩成不可用小图。

| 页面 | 必需主画板 | 必需状态画板或动态面板 | 主要动作 |
| --- | --- | --- | --- |
| 登录／注册 | C4 登录、注册页；青蓝换肤对照 | 字段空、校验错误、密码可见、提交中、凭证错误、会话过期 | 登录、注册、保持登录、返回来源页 |
| 项目首页 | C4 动态首页、青蓝对照 | 无项目、新建中、最近项目、项目加载失败 | 新建／打开／继续项目 |
| 生成页 | 照片+提示词、有当前分集 | 空白引导、上传中／失败、缺照片、缺提示词、计划生成中、额度不足 | 选照片、写提示词、选 5/10 秒、生成计划 |
| 计划确认 | 计划摘要与确认 | 计划失败、用户取消、输入改动后失效 | 显示演示额度消耗，明确确认云端生成 |
| 任务状态 | 正在排队／生成 | 连接中断、重连、未知提交、明确失败、成功保存 | 查看 `runId`、阶段、恢复原任务、打开结果 |
| 结果页 | 视频预览、当前选中版本 | 无结果、加载、视频不可播放、生成失败、原版／编辑版、加入分集成功 | 播放、下载可用版本、进入微调、明确加入画布／时间线 |
| 视频微调 | 首尾裁剪、字幕、封面 | 空字幕、草稿未保存、保存中、渲染中、渲染失败、版本切换冲突 | 保存草稿、完成微调、选择原版／编辑版 |
| 画布 | 空白画布、典型工作流、选中节点 | 节点缺输入、节点运行中、成功、失败、结果过期、同步冲突、导出中／失败 | 创建人物、加节点、连线、逐节点运行、排序、导出 |
| 全局状态 | 两主题组件设计板 | 网络离线、401 会话过期、403 无权、同步冲突、Toast／弹窗、焦点／禁用 | 重试、重新登录、明确选择本地或云端 |

精简画板数量的做法：主页面单独画板；同一页面的空白、加载、失败可以做成并列状态画板或 Pen 中清楚命名的状态组，Axure 用动态面板切换。不能只在一张主画板上写注释而没有具体界面。

## 6. 关键交互规则（Axure 必须可点通）

| 编号 | 起点 → 触发 | 目标状态 / UI 反馈 | 阻断与恢复 |
| --- | --- | --- | --- |
| I01 | 登录／注册：输入邮箱密码并提交 | 按钮忙态 → 成功进入项目首页 | 校验错误就地显示；凭证错误保留邮箱；会话过期回登录，保留返回目标 |
| I02 | 首页：创建项目 | 项目与第 1 集创建完成 → 生成页 | 失败留在首页，保留输入项目名并可重试 |
| I03 | 生成：选照片、写提示词、选 5/10 秒 | 有效输入时启用“生成镜头计划” | 无照片／无提示词禁用并解释；上传失败就地重试，不清空提示词 |
| I04 | 生成：创建计划 | 显示计划、任务 ID、额度提示；先等待确认 | 计划失败保留输入；用户取消时不产生付费生成 |
| I05 | 计划：点击确认 | 排队 → 提交 → 生成中 → 保存结果 | 按钮防重复；断线后按原任务 ID 恢复；`unknown` 只查询原任务，不创建新任务 |
| I06 | 任务完成：打开结果 | 播放原始视频，显示版本和来源 | 视频加载失败显示重试；任务明确失败给“修改输入后重新生成”入口，需再次明确点击 |
| I07 | 结果：进入微调 | 原视频为编辑起点；首尾裁剪、字幕、封面；保存草稿后渲染 | 原文件永远保留；渲染失败只重试同一配方，不自动替换时间线版本 |
| I08 | 结果：加入画布 | 选择现有集或新建集 → 增加一个已有视频节点 | 不触发第二次云端生成；目标集失败时结果仍留在结果页 |
| I09 | 画布：创建人物 | 上传一张参考照片、名称、文字设定 → 可复用人物节点 | 照片失败保留名称；人物不是 AI 生成的三视图 |
| I10 | 画布：连接人物／图片＋文本到视频节点 | 节点显示最终参考图与提示词；满足条件可运行 | 一个视频节点只接受一张主参考图；类型错误或环路提示原因；连线本身不付费 |
| I11 | 画布：点击运行当前视频节点 | 保存意图后显示状态；完成后在原节点展示视频 | 逐节点执行，无全图自动运行；当前输入变动时旧结果标记过期，重新生成需明确确认 |
| I12 | 画布：加入整集时间线、拖动排序 | 片段 ID、首尾裁剪与音量随片段移动，预览按时间线顺序 | 连线和节点空间位置不代表播放顺序；已选的媒体版本不被新渲染静默替换 |
| I13 | 画布：导出整集 | 导出中 → 可打开／保存 MP4 | 没有片段时禁用；导出失败保留时间线并可重试 |
| I14 | 任一页：切换主题 | 全页、弹窗、空态和任务组件即时换肤 | 输入、节点位置、已选版本、任务 ID 与时间线顺序不变 |
| I15 | 桌面同步：同一资源两端改动 | 显示本地／云端摘要、时间与版本，逐资源选保留哪版 | 取消则暂停该资源同步；覆盖前备份本地项目；第三次并发变更须重新提示 |

### 画布节点菜单和执行边界

首版可用节点：文本、参考图片、主体／人物、视频、时间线。音频和导演台可在参考截图里出现，但原型中应置灰并标注“暂未开放”，不模拟可执行流程。节点连线表达引用，视频节点可手动生成或承载已生成素材；生成成功后用户仍须明确点击加入时间线。画布可以无限平移缩放，不画成被外框圈住的固定白板；顶部集信息只是浮层或导航，而非限制节点活动范围。

## 7. Axure 文件构建规格

建议页树：`00_设计系统`（主题变量、组件与状态）→ `01_账号` → `02_项目首页` → `03_生成` → `04_计划与任务` → `05_结果与微调` → `06_画布` → `07_全局异常`。同一页面使用动态面板管理 `empty / ready / loading / failed / success / unknown / conflict`；复用主导航、任务状态、结果卡、确认弹窗。用可点击热点与明确的返回路径连接所有主步骤。

原型变量建议：`skin`、`isLoggedIn`、`projectId`、`episodeId`、`photoReady`、`promptReady`、`clientRequestId`、`runId`、`runState`、`selectedVideoVersion`、`syncConflict`。变量仅模拟界面状态，不保存真实密钥或真实账号。一个示例项目使用“小狗做饭”作为演示数据即可；所有文案保留人或动物都适用的通用入口，不把小狗场景写成产品限制。

推荐 Axure 交互：动态面板切换状态，条件案例处理缺输入与错误；全局变量跨页保留演示上下文；必要的重复列表可用 repeater。官方能力参考：[动态面板](https://docs.axure.com/axure-rp/reference/dynamic-panels/)、[变量](https://docs.axure.com/axure-rp/reference/variables/)、[自适应视图](https://docs.axure.com/axure-rp/reference/adaptive-views/)、[交互动作](https://docs.axure.com/axure-rp/reference/actions-list/)。每页备注需列触发条件、展示文案、目标页、错误与恢复路径；不要把“生成中”演示计时器当成真实后端承诺。

## 8. Pen 文件构建规格

1. 保留现有探索画板和全局变量；在同一 `.pen` 文件里建立 `00 Foundation` 与共享组件区，然后补 `01 登录`、`02 首页`、`03 生成`、`04 任务`、`05 结果`、`06 微调`、`07 画布`、`08 异常状态`。不覆盖原 `bVBmG`、`WIeXo`、`UeaSP`、`lxBAB`、`N0147`、`EvIxh`、`G7shnl`、`qqwZg`、`ZH2AT`。
2. 基础组件至少有两套主题的按钮、输入、上传框、任务进度、结果卡、视频版本选择、节点、时间线片段、弹窗、Toast、空态。每个组件必须有 hover、focus、disabled、loading、error 的必要变体；必要状态需有真实短文案。
3. 每个主页面放全局导航与主题入口；桌面窗口栏固定 48px。青蓝换肤至少给生成、画布、结果和通用状态做同布局对照；登录与首页保持 C 方案视觉，登录状态也需在两主题可读。
4. 动效在 Pen 用 shader／分层说明，在可运行 HTML 预览中验证真实节奏；若 Pen 不播放动画，静态画板必须标注动效层、时长和 reduced-motion 静态回退。不要把 HTML 预览称作 Pen 原型。
5. 页面画板中的业务动作、状态名称、`runId` 与分集关系要与 Axure 一致；Pen 命名与 Axure 页树建立一一对应表，设计师交付时写入交接页。

## 9. 评审与验收

- 从未登录出发，能在 Axure 中点完 I01–I08，再在宽屏点完 I09–I13；失败、断线、额度不足、`unknown`、同步冲突各至少有一个可返回正常流程的交互路径。
- Pen 中生成、画布、结果、登录／首页和全局状态都呈现 C4；青蓝换肤的同一页面组件一一对应，画布不是固定边界；桌面 48px 原生栏与网页导航不混淆。
- 生成任务的 ID 可见且恢复不重复发布；画布逐节点运行；编辑版与原版都可访问；时间线加入与替换是显式动作。
- 空白、加载、失败至少覆盖生成、结果、画布三大页面；文案指出下一步，不只显示转圈或“出错了”。
- 移动原型没有画布入口，却能登录、生成、看状态、看结果与微调；窄屏和 reduced-motion 的行为均可演示。
- 交付包包括 `.pen`、Pen 画板索引、动效预览、Axure `.rp`、原型预览地址或 HTML，以及本文件。缺任何一项应在交付说明里明确列为未完成，不得用静态截图代替可点通交互。

## 10. 给设计师的先后顺序

先完成全局 token 与组件，再画**生成 → 任务 → 结果**主路径，然后补画布和人物／时间线，最后补空白、加载、失败、冲突和移动适配。每完成一条可点击路径就用演示项目走一遍，再扩展主题。这样可尽早发现“某页好看但返回路径或任务身份丢失”的问题。
