## 1. 目标、用户与成功定义

用户选择的定位句：**说出一个念头，让 Agent 把它拍成故事。从创意、分镜到视频片段，Agent 主导推进；你在关键步骤选择和确认。**

目标用户：①仅有一句话/关键词、不会写分镜的新手；②已有剧本但不想手动拆镜的人；③有参考照片，希望保留人物并只重做某一镜的人。用户任务是拿到一条可播放、可修改、可导出的**15 秒微故事**，而非三条互不相干的片段。

本版“故事”的最低标准：3 个连续 5 秒镜头分别表达**起因、变化、结果**；同一主体/画风跨镜头可辨认；画面顺序和分镜顺序一致；用户不进画布也能看完初稿并导出。总成片时长目标 15±0.5 秒。30 秒扩展故事和约 60 秒以上短片属后续范围，不写成首版能力。

## 3. 信息架构与主流程

```text
首页一个输入框
 ├─ 让 Agent 拍成故事 → 三篇完整故事方向 → 选 1 篇
 └─ 用我的内容开始 → 保留原文 → 选“15 秒微故事”或现有单镜头
        ↓
 明确创建/选择项目与分集 → Agent 在该集画布形成 3 镜分镜
        ↓
 用户审分镜、角色/参考、总费用上限 → 确认拍摄
        ↓
 Agent 按批准的 3 项任务拍摄 → 时间线自动装配 → 15 秒预览
        ↓
 只重做一镜（另确认费用）／画布精修／导出 MP4
```

一张画布仍对应一集。故事预览是面向新手的**线性视图**；画布是同一份数据的编辑视图，不要求新手拖连线。移动端展示线性分镜与任务/结果，不注入画布编辑器。用户若有完整剧本，原文永久可找回；Agent 的改写和分镜是新版本，不覆盖原文。项目建立/关联前不发视频请求。

## 4. 页面、按钮与状态

以下为本需求的主按钮，不包括既有全局导航、账号、主题切换。名称为验收文案；若架构或设计提出改名，须回到产品评审。

### H0 首页：说出一个念头

**组件**：一个可扩展输入框“写下一个念头、关键词或剧本”；示例短语可点击填入，不自动提交。Agent 路径建议 1–200 字；已有剧本路径至多 10000 字。固定主按钮 **2 个**：`让 Agent 拍成故事`、`用我的内容开始`。单镜头入口保留在“创作”页或后续作品设置，不在首页再堆第三块独立表单。

- 点 `让 Agent 拍成故事`：登录且文本有效时创建/恢复同一个故事方案请求，进入 H1 加载态；只调用文字模型，不创建项目或视频任务。未登录提示登录，输入保留。
- 点 `用我的内容开始`：进入 S0 作品设置；不调用 Agent；原文保留。可以选择 15 秒故事，由 Agent 在后续结构化拆镜；该文本调用须明确展示，不得把“直接开始”理解成“零 Agent 调用”。
- 空输入：两个按钮禁用并说明“先写下一句话”；>200 字只禁用 Agent 三方案按钮，不阻断自有内容路径；断网保留草稿。

### H1 三篇故事方向

Agent 返回**恰好 3 篇不同故事**。每张卡有标题（≤30 字）、一句话情节（≤80 字）、起因/变化/结果各一句（每句≤80 字）、结尾、预计 15 秒与风格。主交互：**3 张可选故事卡**、`换三篇故事`、`选这篇继续`、`返回修改想法`，共 **6 个**；未选择时“选这篇继续”禁用。选中可查看/修改故事标题和三段情节；文本模型重新运行不扣视频额度，但提示“将生成新版本”并使用新请求 ID。旧草案与选中状态可恢复。

Agent 不得把当前“三版单镜头提示词”返回结构冒充三篇故事；三篇不得只改形容词、不得凭空描述未上传照片的内容。模型不可用、超时、结果格式错误、内容不合规时显示具体状态、`重试原请求/查询状态`（按真实协议）及`用我的内容开始`，不得出现假故事卡。

### S0 作品设置

**组件**：输入原文摘要、所选故事、项目归属、分集归属、模式。主交互 **5 个**：`新建项目`、`加入已有项目`、`15 秒微故事`、`5 秒单镜头`、`创建并继续/加入并继续`。项目与模式未明确时继续禁用。创建成功才进入 B0；失去响应时按同一项目请求 ID 查询，不自动重复建项目。桌面未登录的本地草稿可保留，但 Agent/视频调用需登录云端；不会自动同步到网页。已有项目内只添加新故事，不覆盖既有分集与镜头。

### B0 Agent 分镜与画布

进入后 Agent 按选定故事**自动建立 1 个故事总览、1 个角色/视觉参考、3 个文本分镜、3 个视频待拍节点、1 条时间线**；节点/边按现有画布约束和有效数据格式生成。页面默认是三张按时间顺序的分镜卡（`0–5s 起因`、`5–10s 变化`、`10–15s 结果`），旁边有“画布已建立”小地图。每张卡显示画面目标、动作、场景、镜头语言、参考图来源、最终视频提示词、状态和可编辑入口；未生成视频时必须标记“待拍摄”。

主交互：每镜 `修改分镜`（3 个）、`重新规划分镜`（1 个，文字/参考草案，不调用视频）、`替换参考照片`（1 个，可选）、`打开画布精修`（1 个）、`确认分镜并查看费用`（1 个）、`返回选故事`（1 个）。合计 **8 个**，其中 3 个按镜头重复。所有文本和参考更新产生新的分镜修订；旧视频与已确认的旧报价不能静默绑定新修订。若无用户照片，Agent 必须自动准备可用参考；没有可用参考时说明阻塞，不能让用户走到拍摄确认。无法保证跨镜一致时显示风险提示，并允许用户改角色/参考后重规划。

### Q0 总预算与拍摄确认

清楚列出每镜 5 秒、模型/质量、预计费用/额度、可能的参考图成本、总费用上限、已含/不含的内容、失败和重做的计费规则。主按钮 **2 个**：`返回修改分镜`、`确认拍摄 3 个镜头`。未取得服务端有效价格、额度不足、参考缺失、分镜修订变化或账号状态失效时确认禁用；说明原因与下一步。

一次确认绑定**项目 ID、分集 ID、故事 ID、分镜修订/哈希、3 个镜头 ID、每镜输入快照、模型/时长、费用上限、确认 ID**。任何一项变化须重新报价。确认成功后服务端持久化 3 条提交意图，再按架构决定的安全并发数运行；页面关闭和断线后查询原任务。不得在没有总确认时自动发起视频任务，也不得因供应商响应未知就再 POST。额外镜头、用户主动重做或总费用上限变化必须二次确认。

### R0 拍摄进度

每镜有 `待提交/排队/生成中/下载中/已完成/失败/状态待确认`；顶部显示已完成数量和当前预计进度，**不伪造 ETA**。主交互 **3 个**：`查询原任务`、`查看分镜`、`查看已完成片段`。刷新、跨端重开后使用同一故事运行 ID 恢复。单镜失败时保留其他成功片段，并给出`重试失败镜头`，先检查是否原任务可查询；若需要新付费任务，先回 Q0 为该镜头单独报价。

### F0 初稿、精修与导出

成功片段按分镜顺序自动加入本集时间线，生成可播放 15±0.5 秒初稿。页面显示故事标题、三镜头、选用版本、字幕与总时长。主交互 **5 个**：`播放初稿`、`只重做这一镜`（在单镜菜单中）、`打开画布精修`、`导出 MP4`、`查看费用与任务记录`。主动重做产生新版本，旧片仍可回选，已导出文件不被覆盖；时间线仅在用户明确选择替换后采用新版本。导出失败保留可播放初稿，支持重试同一渲染任务。若某镜头未成功，不能标成“已成片”；可进入部分成功处理页。

## 5. Agent 输出与服务契约（供架构设计，不预设实现）

| 对象 | 必含字段/规则 | 持久化与校验 |
| --- | --- | --- |
| `StoryIdeaSet` | 请求 ID、原文快照、3 篇故事、模型/版本、状态、错误码 | 每篇恰好 3 段叙事；可恢复、可选中；与单镜头 `PromptIdeaSet` 区分 |
| `StoryPlan` | 选定故事、项目/分集、角色设定、3 镜分镜、原文引用 | 分镜顺序稳定，提示词和用户原文分开；分镜修订号递增 |
| `ShotReference` | 每镜主参考图、角色/风格锚点、来源和权限 | 无照片主路径可用；不得把参考图生成失败当成视频成功 |
| `StoryQuote` | 分镜修订哈希、3 项明细、币种、单价来源、总上限、有效期 | 服务端签发/复核；价格未知不允许确认；旧报价不可用于新修订 |
| `StoryRun` | 运行 ID、批准的 3 镜列表、确认 ID、每镜操作 ID/供应商任务 ID、事件序号 | 提交意图先落库；未知状态只查询；结果/扣费可追溯 |
| `StoryResult` | 每镜已选视频版本、时间线、字幕、预览和导出任务 | 一集一画布；重做留旧片，跨端恢复并保留同一故事 ID |

故事输出和视频输入均需做长度、结构、引用、账号权限、禁用内容和资源类型校验。模型返回“3 个看似故事的空白模板”、三个相同结尾、无剧情变化、引用不存在照片，均不得进入付费拍摄。具体模型供应商、无照片技术路径、队列并发、事务与事件协议由架构方案决定；产品要求是用户可见结果与安全边界，不指定底层库。

## 6. 异常、边界与兼容

- **没灵感/输入空白**：显示 2–3 个示例关键词，可填入但不自动请求；历史草稿可继续。
- **已有完整剧本**：保留原文；Agent 拆镜须显示“将按你的剧本规划 3 镜头”，用户可修改和退回；超过 15 秒的信息不能静默删除，需提示压缩/扩成未来 30 秒。
- **未登录/断网**：允许保留本地输入；Agent、付费拍摄不可暗中排队；登录后继续原草稿。退出账号不可显示前一账号故事。
- **视觉参考失败**：三镜分镜仍可看和编辑，拍摄确认禁用；支持按具体参考重试或替换照片。用户不提供照片时仍必须有可用无照片路径。
- **价格变化/额度不足**：旧报价失效，清楚显示新旧价及原因；不自动扣费。
- **响应丢失、浏览器关闭、跨端重开**：同一故事/镜头/操作 ID 恢复，不二次创建付费提交。状态未知不显示成功或失败的假结论。
- **部分片段成功**：成功片段可看；失败片段能查原任务或单独报价重做；不得把 10 秒拼接结果说成 15 秒成片。
- **重做/删除**：只影响选中镜头；旧结果和已选时间线版本保留，删除须遵循现有项目数据规则。
- **移动端**：使用线性分镜、进度、预览与导出；`打开画布精修`显示“请到网页或桌面打开”，不渲染不可用编辑器。
- **旧项目与旧三版提示词**：数据可读取且不迁成假故事；现有单镜头生成、画布手动运行、字幕/微调、整集导出不回归。

## 8. 量化验收、官网与 README 发布闸门

| 宣传候选句 | 数值定义 | 通过门槛与证据 | 不通过时文案 |

## 9. 最终全链路测试与截图交付

测试使用独立账号和同一 `storyId/runId`，至少提交一条真实 15 秒三镜头任务；在价格确认前记录额度与任务数，在确认后记录实际供应商任务和费用。**不以模拟模型或假视频替代最终验收。** 必须交付以下截图/证据并标明网页、桌面或移动平台：

1. `E01` 首页输入关键词与两个动作（空态/有效态）；
2. `E02` Agent 返回 3 篇完整故事，选择其中一篇；
3. `E03` 项目/分集归属与原文保留；
4. `E04` Agent 自动建立的三镜分镜及**画布节点/连线/时间线**；
5. `E05` 三个 5 秒任务及总费用上限的确认页，确认前视频任务数为 0；
6. `E06` 拍摄中每镜状态、刷新后同一运行恢复；
7. `E07` 三段结果按序进入时间线，15±0.5 秒可播放初稿；
8. `E08` 导出 MP4 可独立打开、时长/画面/字幕正确；
9. `E09` 单镜失败或主动重做仅影响该镜，旧版与其余两镜仍在；
10. `E10` 真实任务/账单、没有重复付费提交、数据与截图的运行 ID 相符。

异常态补充：空输入、Agent 配置错误、无照片参考失败、额度不足、报价过期、单镜失败、供应商状态未知、导出失败、两个账号隔离、桌面未登录/未同步。测试报告对每项写**通过/失败/阻塞**、候选代码/部署版本、环境、步骤、预期/实际、截图路径与遗留风险。最终代码审查以这份实际跑通的候选版本为准。

## 10. 审核点

用户需先审核架构会话交付的方案，重点看：①无照片从一句话开拍的可靠路径；②三镜一次总确认是否满足费用控制；③故事与现有画布/项目 DSL 如何同源且跨端；④真实报价、失败/重做、断线不重复扣费；⑤线上已有 `provider_error` 如何在 P0 消除。**架构方案获批后**才由架构拆给前后端和测试会话。`¥39.9`、90 秒、10 分钟都是带发布闸门的目标，用户可在架构审核时调整。
