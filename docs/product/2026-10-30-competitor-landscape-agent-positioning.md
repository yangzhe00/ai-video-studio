# AI Video Studio｜竞品格局、产品取舍与 Agent 职责

**研究日期**：2026-10-30（北京时间）｜**性质**：产品分析与 GitHub README 文案候选，未改 README。
**本项目快照**：当前共享工作树 `HEAD dc066d2`，仍有多会话并行未提交修改；下文“已实现”指本次读到的代码，不自动等于公网已可用。“已验证”以独立测试记录为准。
**研究方法**：选覆盖“想法→脚本/分镜→视频→剪辑/导出”的代表性产品；只使用厂商官方产品页、帮助中心和本仓库代码/测试。厂商页面证明其**公开宣称支持**的能力，不等于我们做了同条件实测。市场产品更新很快，正式放 README 前应重核日期与页面。

## 1. 市场结论

市场已经出现多个“一句话到视频”、Agent、分镜、画布及局部重拍产品。因此 **“有 Agent”“能自动分镜”“一键成片”“可以只重做一镜”本身不是独家优势**。最直接的竞争对手是即梦、Runway Agent、海螺视频 Agent、Google Flow 和 InVideo；可灵、PixVerse、Pika、Luma 更偏生成模型/镜头控制；CapCut、Adobe Firefly 更偏编辑工作台与内容生产。这是按用户任务做的分组，产品之间有交叉。[Sora 的网页、App 和 API 已由 OpenAI 官方宣布停止服务](https://help.openai.com/en/articles/20001152-what-to-know-about-the-sora-discontinuation)，因此它是历史参照，不列为当前可用竞品。

我们的合理定位是一个**待验证的窄场景**：第一次做视频的人，输入一个念头，先从 3 篇完整故事中选 1 篇，看到 3 个连续 5 秒镜头，再一次确认这 3 个镜头的费用与参考素材，让 Agent 组织拍摄，最后可只改一镜并导出 15 秒微故事。核心卖点若能成立，应是**从空白到可控制的初稿更省心、费用更可预期、断线后结果找得回**。这不是模型画质领先的主张，且三项体验优势都需要与竞品实测。

## 4. “Agent 到底帮用户做了什么”——按真实状态回答

以“**小狗做饭并上菜**”为例：当前文字服务的代码目标是给**同一个 5–10 秒镜头**写三种拍法，用户选一版后上传照片、选分集、确认 5 秒任务；它**不会**自己写三篇完整故事，也不会自动在画布铺出三镜。P1 才把它升级为“三篇完整故事供选 → 选中一篇 → 起因/变化/结果三镜 → 审费用 → Agent 组织拍摄”。这个区别应在产品介绍里始终讲清楚。

| 阶段 | 当前代码里的职责 | 用户可控制的点 | 当前验收状态 |
| --- | --- | --- | --- |
| 想法 | 文字模型可把一个关键词写成**同一单镜头**的 3 版标题、描述和图生视频提示词；有输入长度与结构校验、请求 ID、结果查询与保存 | 用户选一版、编辑最终提示词；文字步骤不创建视频操作 | 代码已接入；公网真实调用曾失败，修复前只能说“开发中” |
| 镜头计划 | [`planImageVideo`](../../packages/agent-core/src/index.ts)按用户输入做**确定性校验和单步骤计划**，标注需要批准；这不是大模型自主写分镜 | 用户检查参考照片、提示词、目标分集并批准 1 次 5 秒任务 | 代码存在；真实全链路另需验收 |
| 执行与恢复 | 服务端为已批准任务留 `operation` 与外部任务 ID；后台提交可灵、轮询、下载/保存结果；断线或状态未知时尝试查原任务 | 用户查看状态、结果与失败，不应因刷新被自动再次扣费 | 有实现与定向测试；不能由此推断公网零重复扣费 |
| 剪辑建议 | 候选代码允许模型提出结构化裁剪、镜头排序、字幕和已确认配音素材的建议；校验资源、版本和动作，再由用户逐条确认 | 用户可以拒绝建议，继续手动剪辑 | 本地定向测试；真实模型联调与公网发布未通过 |
| 15 秒故事（P1） | **计划新增**：3 篇完整故事、三镜分镜/画布节点、无照片参考、三镜预算、拍摄编排、15 秒初稿 | 用户选故事、改分镜、确认费用、重做某一镜 | 尚未开发验收完成，不能描述为已发生 |

**重要术语**：视频像素由可灵等第三方生成模型产生，Agent 的价值在于把用户意图变成可审的提示词/分镜并组织任务、状态和编辑建议；不能写“自研 Agent 生成底层视频模型”。当前文字接口是有约束的结构化文本生成，[Cursor 适配器](../../apps/api/src/idea-cursor.ts)还明确要求“不使用工具”；`planImageVideo` 是确定性流程规划，不是会自由选择工具的自主 Agent。开发流程中的 Codex 架构、前端、后端、测试会话是**研发协作**，与面向用户的产品 Agent 分开介绍。

## 5. 能否把“更适合小白”写进 README：验证方案

与即梦、Runway Agent、海螺 Agent、CapCut、InVideo 至少选 3 家做同条件新手任务。使用相同的 3 个题材（人物叙事、动物叙事、无照片产品短片），限制为 15±0.5 秒或各产品最接近时长；统一画幅、画质档、是否允许素材库/参考图，记录不一致项。至少 24 名首次使用者做交叉任务，随机平衡产品顺序，记录：

- 从输入到确认拍摄的**主动操作时间**、点击/返回次数、求助次数和完成率；等待时间单列。
- 从确认到可播放初稿的 P50/P90、失败率、人工重试次数、可恢复率、重复付费提交数。
- 实际支付/消耗金额、生成片段数、重做成本、导出是否含水印；仅在同条件套餐/额度下对比。
- 3 名盲评按“起因—变化—结果可辨”“主体一致”“画面可用”打分；质量不低于对照才谈效率优势。

若要公开“新手更快”，门槛沿用 [故事 PRD 第 8 节](2026-10-30-agent-story-flow-prd.md)：主动操作时间中位数至少比对照低 30%，成片质量不低于对照，并公开日期、样本量、题材、套餐条件。未完成测试时只写**定位与设计目标**，不写竞品优劣的量化结论。

## 6. GitHub README 候选文案（按状态选择，不要整段原样发布）

### 现在可以用的写法（如实区分候选与公网）

> AI Video Studio 面向想从一个念头开始创作短视频、又希望逐镜控制结果的用户。仓库已经实现参考照片驱动的 5 秒镜头任务、分集画布、时间线及剪辑/导出流程；视频任务在用户确认后提交，服务端保存任务状态以便查询与恢复。文字 Agent 的三版单镜头提示词和 Agent 剪辑建议仍在供应商联调及验收中。代码实现与公网可用是不同状态，请以对应版本的测试记录为准。

### P1 真实闭环通过后才能替换的写法

> 说出一个念头，让 Agent 把它拍成故事。Agent 提供三篇完整故事供选择，并把选中的故事规划为同一集的三个 5 秒镜头；用户检查分镜和费用后，Agent 组织拍摄、装配 15 秒初稿。用户可只重做不满意的一镜，保留其他片段和原版本。

**README 的建议结构**：首屏一句定位 + 4 步流程图 + `已上线 / 测试中 / 规划中` 功能表 + “Agent 的职责与人的确认点” + 技术架构 + 验收/限制 + 本分析文档链接。竞品长表放在本研究文档中，README 只留一段“适合谁、与通用剪辑器的取舍”并链接此处；避免页面很快因竞品版本变化失效。仓库目前没有选定开源许可证（见 [`README.md`](../../README.md)），不要在 README 自称“开源替代品”。
