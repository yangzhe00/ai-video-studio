# AI Video Studio 前端开发规范

> 适用范围：本仓库的网页端、macOS 桌面端、移动端，以及被它们复用的前端包和插件。依据 2026-10-29 的仓库结构编写；改动架构时须同步更新本文件。

## 1. 技术栈与目录职责

| 目录 | 职责 |
| --- | --- |
| `apps/web` | React + TypeScript + Vite 网页入口；会话、云端 API 适配和页面组合。 |
| `apps/desktop` | React + TypeScript + Tauri 桌面入口；原生窗口、本地文件、桌面适配和页面组合。 |
| `apps/mobile` | Expo + React Native 移动端入口；使用原生组件和移动端适配。 |
| `packages/components` | 网页端与桌面端共用的业务展示组件、页面骨架和状态组件。 |
| `packages/ui-web` | 网页端与桌面端共用的 Web 控件及生成页等 Web UI。 |
| `packages/ui-native` | React Native 专用展示层。 |
| `packages/design-tokens` | 全局颜色、间距、圆角与换肤变量。 |
| `packages/project-core`、`packages/project-schema` | 项目数据、校验、迁移和不依赖 UI 的业务规则。 |
| `packages/plugin-sdk`、`plugins/*` | 功能声明与独立功能模块；应用负责显式接入页面。 |

使用 `pnpm` workspace 包名导入跨包代码，不通过 `../../` 穿透其他包的 `src`。新增包必须声明 `package.json` 的 `exports` 和 workspace 依赖。业务规则不要分别复制到 Web、桌面和移动端。

## 2. 组件复用边界

1. 网页端和桌面端同时使用的页面结构，先放入 `packages/components`；通用按钮、状态、主题和生成控件放入 `packages/ui-web`。应用层传入数据、回调和平台能力，不在共享展示组件中直接调用 Tauri、Node、文件系统或服务端密钥。
2. 页面只在视觉和交互确实一致时共用同一个 React 组件。平台差异由 props、插槽或适配器表达，避免复制整个页面后分别维护。现有共用实例包括 `StudioShell`、`ProjectHome`、`ResultsPage`、`CanvasPage` 和 Web 版 `VideoEditor`。
3. 移动端不能直接使用 DOM 组件或 CSS。与 Web/桌面共享类型、项目规则、编辑命令和插件契约；界面由 `packages/ui-native` 或插件的 `native` 入口实现。画布仅接入 Web/桌面，视频编辑插件可分别提供 Web 与 Native 视图。
4. 插件通过 `FeaturePlugin` 声明 ID、依赖、平台和能力。声明不会自动渲染页面；接入方必须显式注册、提供入口、数据和回调。不要把第三方密钥、绝对本地路径或平台实现放进插件描述。

## 3. 页面与导航

- 网页端使用 `StudioShell` 及侧边导航；不要渲染桌面原生窗口标题栏。桌面端使用 `StudioTitleBar native`，窗口栏高度按现有 48px 设计。
- 首页、创作、画布、结果、资产均应有独立入口。未打开项目时仍可进入各工作区，并显示对应空状态和创建/选择项目入口。
- 一张画布对应一集；视频节点是镜头。画布按节点逐个运行，生成结果再加入整集时间线。画布支持平移、缩放、节点连线和节点旁编辑框，不以固定尺寸容器限制节点位置。
- 页面切换不得清空尚未完成的云端任务。恢复入口要能凭任务 ID 查询同一任务。

## 4. 样式、主题与动效

- 当前默认视觉方向为 C4「奶油胶片」。设计基准见 `design/ai-video-studio-ui-options.pen` 与 `design/interaction-clickthrough.html`；实现以已批准的页面交互为准。
- 颜色、表面、边框、文字、画布线条、圆角等使用 `packages/design-tokens/src/tokens.css` 中的 `--avs-*` 语义变量。主题通过根元素的 `data-skin` 切换；目前有 `cream-film` 和 `cyan-night`。新增皮肤优先补齐同一组变量，避免为每套皮肤复制页面结构。
- 样式按职责放置：全局变量进 `design-tokens`；共享组件样式进 `components`/`ui-web`；插件专属样式留在插件；仅平台特有样式留在 `apps/*`。修改共享视觉时同时检查 Web 与桌面，不用应用级 CSS 长期覆盖共享组件来修补布局。
- 遵守现有入口的 CSS 导入顺序，新增样式先确认包的 `exports` 可解析。避免写死窗口宽高；窄窗口不得出现遮挡、覆盖或横向溢出。动画应响应 `prefers-reduced-motion`。
- 图标优先使用 `StudioIcon`；交互控件使用语义化元素和明确的 hover、focus、disabled、loading 状态。

## 5. 数据与异步任务

- Web 请求集中通过 `apps/web/src/api.ts` 的同源 `/api` 适配；桌面云端请求通过 `apps/desktop/src/lib/cloud.ts` 及平台接口。共享 UI 只接收类型化数据和回调。
- 云端 Agent 任务、视频生成和渲染必须保留稳定的客户端请求 ID / 操作 ID。提交前记录意图；网络响应丢失时查询原任务，不能直接创建新的付费任务。任务 ID 与已收到的状态须能在刷新、重进项目后恢复。
- Web 任务进度使用 SSE，并用任务快照查询兜底；组件卸载时关闭 `EventSource` 和定时器。界面区分待确认、排队/运行、完成、失败，不能把「请求超时」直接显示为「生成失败」。
- 项目和画布改动通过命令与修订号保存；出现云端同步冲突时保留当前数据并交给用户处理，不静默覆盖。原始视频与编辑版本分开保存。
- API 密钥只存在服务端；前端不得读取、打包或展示 `KLING_API_KEY` 等服务凭证。

## 6. 状态、可访问性与文案

- 每个工作区至少覆盖：初始空白、加载、成功、失败、未知/待确认、无项目、无权限或资源缺失等相关状态。优先复用 `StatePanel`；错误文案说明用户可采取的下一步。
- 提交按钮在进行中防重复触发；禁用状态必须有原因。付费生成前保留明确确认步骤，不在页面渲染或刷新时自动提交。
- 按钮和输入框提供可辨认名称；图标按钮有 `aria-label`，当前导航有 `aria-current`，异步状态可被辅助技术读到。键盘应能完成主要表单与节点连接操作。
- 提示、空状态和错误文案使用简明中文；内部模型名、密钥、原始异常堆栈和实现细节不进入普通用户流程。

## 7. 开发与验收

1. 改共享组件时，至少运行受影响包及 Web/桌面构建：`pnpm --filter @ai-video/components test`、`pnpm --filter @ai-video/web test`、`pnpm --filter @ai-video/desktop test`，以及对应的 `build`。改项目规则时加跑 `@ai-video/project-core` 测试。
2. 运行 `pnpm check:boundaries` 和 `git diff --check`。不要把 `vite` 能启动等同于 Tauri 已启动；桌面壳改动需用 `pnpm tauri dev` 实际打开验证。
3. 视觉变更在 Web 与桌面分别核对，至少覆盖常见宽屏与窄屏、两种皮肤、空白/加载/失败/成功状态。截图检查错位、遮挡、溢出和点击热区；涉及画布时实际拖动节点、连线、缩放并刷新确认保存。
4. 测试优先覆盖用户行为与数据边界：导航、表单、请求去重、任务恢复、同步冲突、画布命令和编辑命令。不要只写与实现代码同构的断言，也不要用测试截图代替真实运行验收。

## 8. Web H5 响应式布局（2026-10-30）

- 以 CSS `@media` 切换布局，不用整页缩放。`>830px` 使用 236px 完整侧栏；`641–830px` 使用 64px 图标侧栏；`≤640px` 使用顶部品牌栏、底部五项导航和账号/项目抽屉。Web 宿主用 `StudioShell mobileNavigation` 开启手机导航；桌面宿主保留原来的窗口栏和侧栏。断点必须与 `apps/web/src/App.tsx` 的 `matchMedia("(max-width: 640px)")` 一致，旋转或调整窗口时同步切换手机画布概览。
- Web 工作台先声明 `height: 100vh` 作旧浏览器回退，再声明 `height: 100dvh` 跟随浏览器可见区域；取消固定的 680px 最小高度。底部导航和抽屉使用 `env(safe-area-inset-bottom)`，弹窗还要考虑顶部安全区。`apps/web/index.html` 的 viewport 配置包含 `viewport-fit=cover`。短屏内容放入可滚动的页面区域，不让操作按钮被底部导航永久遮住。
- 宽度优先用 `min()`、`max()`、`minmax(0, 1fr)` 和百分比；标题可在有上下限的 `clamp()` 中使用 `vw`；抽屉宽度限制为 `min(84vw, 320px)`。避免按设计稿给主内容、输入框和视频设置固定像素宽。手机输入框保持至少 16px 字号，主要触控按钮至少约 44px。
- 手机 H5 的生成表单、项目库、结果、资产、登录、弹窗、视频微调应为单列或可换行布局；多个快捷入口可以局部横向滚动，但 `documentElement.scrollWidth` 不得大于视口宽度。两套 `data-skin` 主题继续使用语义变量；动画仍遵守 `prefers-reduced-motion`。
- 无限节点画布只在平板/电脑 Web 和桌面端挂载。手机 H5 的“画布”入口展示分集概览，并提供“继续生成镜头”和“查看生成结果”；作品设置不提供手机节点编排选项。视频剪辑仍可在手机 H5 使用。React Native 移动端依然使用独立的原生展示层。
- 视觉回归至少包含 `320×568`、`375×667`、`390×844`、`412×915`、`640×800`、`641×900`、`768×1024`、`1440×900`；手机短屏需要验证向下滚动后表单按钮、最近内容可到达，640/641px 要专门检查导航断点。核对登录、首页、生成、项目、空结果、资产、弹窗、手机画布概览、两种主题；平板和桌面核对实际节点画布。运行共享组件、Web、桌面相关测试和构建。详见同目录的 `web-h5-responsive.md` 与 `web-h5-test-report.md`。

本规范描述当前项目的前端开发边界。现有代码若未完全满足某条规则，后续改动应逐步收敛；不要为了形式上的统一而破坏已运行的功能或数据兼容性。
